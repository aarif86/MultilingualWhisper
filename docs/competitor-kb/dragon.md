# Dragon (Nuance / Microsoft)

> Made by Nuance Communications (acquired by Microsoft, 2022); the dominant professional/medical dictation suite for 25+ years. Three live product lines: **Dragon Professional** (Windows desktop, one-time purchase), **Dragon Anywhere** (iOS/Android subscription — discontinued for new sales/renewals July 1, 2026), and **Dragon Medical One / DAX** (cloud, healthcare, per-seat subscription via reseller). For Nasar Flow: the closest thing to an incumbent "power user" dictation product, built for English-only enterprise/medical workflows, with zero code-switching or Singlish/Malay/Arabic support — but with by far the most mature correction/command vocabulary and personalization model in the category.

## Facts
- **Maker / founded / funding:** Nuance Communications (speech recognition since the 1990s; Dragon NaturallySpeaking lineage). Acquired by Microsoft in March 2022 for ~$19.7B; now a Microsoft-owned product line, integrated into Microsoft's "Dragon Copilot" / DAX Copilot healthcare push.
- **Platforms:** Windows desktop (Dragon Professional/Legal/Professional Group), iOS + Android (Dragon Anywhere — discontinued for new users July 1, 2026), Windows via Citrix/RDS + browser extension (Dragon Medical One). No native macOS full-text-control product (Dragon for Mac exists but is deprecated/limited); no native Linux.

- **Languages:** Primarily English (US/UK/Australian/Indian dialects) plus a modest set of European languages (French, German, Italian, Spanish, Dutch) for Professional/Anywhere. Dragon Medical One's language support is narrower and vocabulary-specialty driven (medical specialty vocabularies, not additional spoken languages).

## Activation & capture UX
- **Dragon Professional (desktop):** microphone is a persistent hardware/software toggle on the "DragonBar," not a push-to-talk gesture — say **"Wake up"/"Go to sleep"/"Stop listening"** or click the mic icon; it stays hot until explicitly turned off. No ambient/always-listening wake word.
- **Dragon Anywhere (mobile):** tap a mic button to arm listening, tap again or say **"Microphone Off"** to stop; a **"Beep when microphone turns off"** setting exists for eyes-off (e.g., driving) use because the mic auto-times-out after 20 seconds of silence or when a command switches focus away from the Dictation window.
- **Dragon Medical One (cloud, EMR-focused):** a compact floating console (mic icon, sound-level bar, minimize, settings) — toggled by mouse click, hot-key (default push varies), voice command, or a **hand-held microphone button** (PowerMic II/III, Philips SpeechMike). Feedback is a red/green mic icon plus a live volume bar; a **lock icon** overlays the mic when dictation focus is "anchored" to a background window.
- **The Dictation Box** (all desktop-class products): a small standalone text box that auto-launches whenever the target app/window isn't natively Dragon-compatible, so speech is never silently dropped — it becomes a staging area you later "Transfer Text" out of.
- No watch app; no widget-based activation documented for any Dragon product.

## Text insertion
- **"Select-and-Say" / Full Text Control** is Dragon's core mechanism: when the target text field is a recognized standard Windows control (TextBox/RichTextBox or specific supported apps), Dragon reads the *actual visible text* in the field, allowing true select/replace/format-by-voice on existing content, not just typed-in-the-moment dictation. [nuance.custhelp.com — Enabling Full Select-and-Say](https://nuance.custhelp.com/app/answers/detail/a_id/3765/), [KnowBrainer forum thread on developer requirements](https://forums.knowbrainer.com/forum/dragon-speech-recognition/4225-full-text-control-developer-question).
- If the app is **non-standard** (custom-drawn UI, some Electron/web apps, remote/virtualized sessions), Dragon falls back to "recent dictation memory" instead of reading the live text buffer — meaning correction commands work off what Dragon *remembers saying*, not what's actually on screen; this silently degrades the correction experience with no clear warning to the user.
- The DragonBar shows a **green/gray indicator** of whether the current window supports Full Text Control — a genuinely useful, always-visible compatibility signal Nasar Flow lacks any equivalent of.
- Dragon Medical One additionally supports **"anchoring"**: lock dictation focus to a specific window so text keeps flowing there even while the user tabs through other windows in an EMR — solves the "I need to glance at another chart while still adding to this note" problem that a single-focus dictation app can't.
- Known-broken/non-standard cases: web-based EMRs without the DMO Chrome extension, older Office (2003), some Citrix/virtualized sessions where DMO and the target app live on different machines (text has to go through the Dictation Box + a manual "Transfer Text" step — 4 different transfer methods are offered because none work universally; "Simulate Keystrokes" is the guaranteed-but-slow last resort). [Dragon Medical One Unofficial Guide, pp. 34–36].

## Accuracy & personalization
- **Custom vocabulary / word list:** users add individual words via "Add New Word"/"Add that to vocabulary," optionally with a **separate written vs. spoken form** (e.g., written "PACU," spoken "pack-you"; written "Wahrenberger," spoken as it actually sounds) — directly solves the classic problem of acronyms/names that don't sound like their spelling. Bulk import/export of word lists is desktop-only; Dragon Anywhere and Dragon Medical One can only add one word at a time by the end user (bulk add on DMO requires an admin panel).
- **Auto-Texts:** named voice-triggered text macros/snippets ("say the name, get the paragraph") — used heavily by clinicians for consent language, exam boilerplate, counseling scripts. Can include fillable "fields" (`[Date]`) navigated with "Next Field"/"Previous Field"/"Accept Defaults." Auto-Texts sync between Dragon Anywhere and Dragon desktop via a shared cloud account (plain text only — rich formatting is stripped).
- **Accuracy Tuning wizard**: a formal two-part optimization — **acoustic optimization** (retrains on how *you* pronounce words, using accumulated corrections + training samples) and **language model optimization** (updates word-usage statistics from your own dictated/edited documents). Requires an accumulated **acoustic archive** (Dragon retains up to 180 minutes of audio by default) before it will run, and Nuance explicitly recommends scheduling it for idle time because it's CPU-heavy. [nuance.com — About Accuracy Tuning](https://www.nuance.com/products/help/dragon/dragon-for-pc/enx/dps/main/Content/Accuracy/about_accuracy_tuning.htm), [Acoustic Optimizer Scheduler](https://www.nuance.com/products/help/dragon/dragon-for-pc/enx/professionalgroup/main/Content/DialogBoxes/misc/acousticoptimizer_scheduler.htm).
- **Formal correction vs. silent editing** is an explicit, taught distinction: Dragon Anywhere's own docs tell users "it's very important to correct mistakes... correcting mistakes will improve accuracy over time," contrasted with just manually retyping (which teaches the model nothing). Formal correction = select the wrong text (voice or touch) → correction menu appears with ranked alternatives ("choose one," "choose two") → pick, or re-dictate/type, or explicitly "add that to vocabulary."
- **Per-specialty vocabularies** (Dragon Medical One): choose a domain vocabulary (Cardiology, Orthopaedics, Emergency, General Medicine, Clinical Administration for non-medical dictation, etc.) at login — this re-weights word probabilities for the whole session, a coarse-grained but effective personalization lever competitors rarely expose.
- **Single-speaker-per-profile is a hard rule** — Dragon Anywhere's docs warn that if a second person dictates under your login, "their audio will be added to your profile" and degrades accuracy; there is no shared/family profile concept, only separate paid logins.
- Dragon Medical One explicitly needs **no initial enrollment/training session** — profile is created and starts adapting from first use (a deliberate simplification versus classic Dragon NaturallySpeaking's mandatory read-aloud training passage).
- Claimed accuracy: "up to 99%" recognition for Dragon Professional and "over 99%... from the first use" for Dragon Medical One (marketing figures — user reviews below show real-world experience is more mixed, especially with technical vocabulary and non-standard accents).

## Formatting & AI cleanup
- No filler-word removal or generative rewrite layer — Dragon is a faithful transcription engine with rule-based auto-formatting only: dates ("January first two thousand fifteen" → "January 1, 2015"), times, units ("50 milligrams" → "50 mg"), and number/measurement normalization.
- Punctuation, capitalization, and structure are entirely **manually spoken** — users must say "comma," "period," "new paragraph," etc.; there is no punctuation-inference step at all. This is a deliberate design choice for precision/legal-medical documentation but is a materially worse "raw speed" experience than modern AI-punctuation dictation apps.
- Explicit format commands apply to a **selected span**, not automatically to "the last thing you said" (Dragon Anywhere differs from desktop Dragon here — desktop applies "Bold that" to the last utterance by default; mobile requires an explicit "Select ___" first). This inconsistency between the company's own products is a real UX wart.
- No tone/style "modes" (email vs. chat vs. code) and no user-writable prompt/rewrite layer — formatting commands are a fixed vocabulary (Bold/Italicize/Underline/Capitalize/All Caps/Set Text Color/Set Highlight Color), not customizable behavior.
- "Raw vs. polished" toggle does not exist as a concept in Dragon; the closest analog is choosing whether to dictate into a Dictation Box (unstyled, plain-text staging) vs. directly into a formatted document.

## Voice commands
Representative exact phrases (desktop Dragon Professional v16 cheat sheet + Dragon Anywhere + Dragon Medical One docs):
- **Correction:** "Scratch That [x times]" (delete last utterance, repeatable), "Correct That" / "Correct <text>" (opens Correction menu with numbered alternatives — "Choose 1," "Choose 2"), "Select <text>" / "Select <text> through <text>", "Spell That" / "Spell <letters>" (opens Spelling window), "Undo That" / "Redo That", "Resume With <text>" (rewrites everything after a chosen anchor phrase), "Add that to vocabulary," "Do not recognize that word" (blocklist a word), "Delete Word," "Unselect That."
- **Selection/navigation:** "Select All," "Select next/previous <n> words," "Select (first|last|next|previous) (word|sentence|paragraph)," "Go to top|bottom," "Go to end of line/sentence/paragraph," "Insert before/after <text>," "Go back" (returns cursor to pre-command location).
- **Capitalization/formatting:** "Cap <text>," "All Caps On/Off," "Make this uppercase," "Bold/Italicize/Underline That," "Unformat That."
- **Structure:** "New Line," "New Paragraph," "Tab <n> times," "No Space On/Off" (for license plates, SKUs, etc.), "Numeral | Roman Numeral."
- **App/window control (desktop):** "Switch to <window>," "Minimize window," "List all windows," "Start <item name>," "Close window."
- **Mode/mic control:** "Wake up," "Go to sleep," "Microphone Off," "Give me help," "What can I say" (shows categorized command list — navigation/correction/formatting/punctuation).
- **Dragon Medical One extras:** "Anchor speech focus"/"Release speech focus," "Transfer Text"/"Discard Text"/"Recall Text" (Dictation Box control), "Next Field"/"Previous Field"/"Accept Defaults"/"Field Complete" (navigate bracket-delimited template fields), "Hide Dragon"/"Show Dragon," "Manage Vocabulary/Commands/Auto-texts."
- **Custom macros:** Auto-Texts (say the assigned name to insert pre-written blocks) and, on Dragon Medical One only, **Step-by-Step Commands** — a full no-code automation builder (Open Application / Wait / Enter Text / Press Keys / Press Hotkey / Microphone On/Off steps, chainable) that can emulate EMR-specific shortcuts like Epic's "dot phrases," open a website, or print a document, and can be bound to a hand-mic button or hot-key.

## Languages & multilingual
- Auto language **detection**: none. Language is a session-level setting, changed explicitly ("Switch to German") or in Settings — every utterance is interpreted against one active language model.
- **Mixed-language in one utterance:** unsupported. Dragon's language model is monolingual per session; there is no code-switching design anywhere in the docs reviewed.
- Translation: not a feature — Dragon transcribes, it does not translate.
- Per-language quirks documented: dialect-specific punctuation wording differs (US/Canada "period" vs. UK "full stop"; US "exclamation point" vs. UK "exclamation mark"; US/Canada "pound sterling sign" for £ vs. other dialects' "pound sign"), and bracket naming differs (US "brace/bracket" vs. UK "curly/square bracket"). This level of dialect nuance exists only *within* English variants — there's no cross-language blending support at all.
- This is Dragon's single largest structural gap relative to Nasar Flow's core value proposition (Singlish/Malay/Arabic code-switching): Dragon was never designed for multilingual speakers switching languages mid-sentence, only for monolingual professionals dictating in one configured language.

## Privacy & data
- **On-device option exists only for Dragon Professional desktop** — local acoustic/language model processing, no cloud dependency for core dictation (an advantage Dragon shares with Nasar Flow's whisper.cpp approach, but only for the desktop SKU).
- **Dragon Anywhere and Dragon Medical One are cloud-only by architecture** — Dragon Anywhere's own docs state audio is "encrypted and transmitted to our recognition servers in a secure data center," converted to text server-side, and that custom words/auto-texts are likewise "uploaded to our central server." An active internet connection is mandatory for dictation on both products.
- Dragon Anywhere explicitly claims it "does not access content on your device, such as your contacts or your location" — a directly stated (if narrow) privacy boundary.
- Dragon Medical One is positioned for HIPAA-relevant healthcare workflows (cloud architecture, "Nuance cloud server," institutional deployment via IT/Citrix) but the crawled sources here are third-party guides, not Nuance's own compliance documentation — no explicit SOC2/HIPAA certification language was captured in this pass and would need direct confirmation from Nuance/Microsoft's compliance pages.
- No "zero-data-retention" toggle or opt-out language found in any crawled doc; retention for the desktop acoustic archive is described (180 minutes by default) but framed as a *feature* (fuel for Accuracy Tuning), not a privacy control.

## Onboarding & docs
- Dragon Professional/Medical One do **not require an enrollment/training passage** in current versions — profile is created on first login and adapts live (a real UX simplification versus the old NaturallySpeaking "read this paragraph aloud" ritual).
- Dragon Anywhere onboarding: mic permission prompt → dictate immediately; a documented "adaptation phase" is called out explicitly in the user guide — "if you experience recognition errors in the first few minutes, keep dictating... this adaptation phase is particularly important if you speak with an accent," setting expectations up front rather than hiding degraded first-run accuracy.
- Help is organized as long-form **PDF manuals** (Dragon Anywhere User Guide is 46 pages; the third-party "Dragon Medical One: The Unofficial User Guide" runs 55 pages) plus an in-context "What Can I Say" command browser and per-topic HTML help pages (correcting_your_dictation.htm, etc.) — dense, reference-manual tone, clearly written for professional/enterprise users expected to read documentation, not a consumer app's inline tutorial.
- Command cheat sheets exist as standalone one-to-two-page PDF "quick reference cards" per product/version (e.g., "Command cheat sheet: Dragon Professional v16 and Legal v16") — a lightweight, printable, at-a-glance format Nasar Flow could emulate for its own command set.
- No public "status page" or "known issues page" was found for Dragon Professional/Anywhere in this search pass; Dragon Medical One support runs through institutional IT/reseller channels rather than a public self-serve status page.

## User complaints (reviews, Reddit, HN, App Store)
- **Price** is the single most repeated complaint across review aggregators: "$699.99 for Professional Individual," confusing licensing tiers, and paid upgrade cycles; one Capterra reviewer reported paying over $500 expecting free upgrades, then being told they'd need to pay an additional ~$200 for support after the initial 6-month support window expired. [www.capterra.com/p/251641/Dragon-Professional-Individual/reviews](https://www.capterra.com/p/251641/Dragon-Professional-Individual/reviews/).
- **Windows-update fragility**: a 2012 TechRadar/Register-style review cycle and more recent Microsoft Learn forum threads document Dragon becoming unstable, crashing, or requiring restart after OS updates (Windows 10 and Windows 11 both cited); one Microsoft Learn thread is specifically titled "Windows 11 ARM and Dragon" describing compatibility breakage on ARM devices. [learn.microsoft.com/answers/questions/1180932](https://learn.microsoft.com/en-gb/answers/questions/1180932/windows-11-arm-and-dragon), [theregister.com 2012 review](https://www.theregister.com/2012/09/10/review_nuance_dragon_dns_12_voice_recognition_software_review/).
- **Command misfires becoming dictated text (and vice versa)**: a long-standing, still-cited Tom's Guide forum thread describes Dragon literally **typing the words "scratch that"** into the document instead of executing the delete command — the exact failure mode the correction system is supposed to prevent, and a good cautionary example for Nasar Flow's own command-vs-dictation disambiguation design. [forums.tomsguide.com — "types 'scratch that' instead of erasing last spoken phrase"](https://forums.tomsguide.com/threads/dragon-naturallyspeaking-12-0-types-scratch-that-instead-of-erasing-last-spoken-phrase.341793/).
- **Accuracy with technical/numeric content**: reviewers report accuracy noticeably worse than advertised when dictating text with many numbers or technical terminology; one older review cited accuracy "around 70%" against marketed figures well above 90%.
- **Training/learning-curve fatigue**: users describe a real ramp-up period both for the software to adapt to their voice and for the user to learn the command vocabulary; several reviews note the correction workflow itself ("select, open correction menu, choose alternative") adds friction versus just retyping, even though retyping doesn't improve the model.
- **Bugs/support**: recurring complaints about buggy recent updates, weak customer support responsiveness, and (per one older but often-cited review) a sense that Nuance was slow to act on reported bugs.
- **End-of-life anxiety**: 2026-era reviews/trade pieces note user unease that Dragon Anywhere's discontinuation and the multi-year lack of a new Professional version signal Microsoft deprioritizing the consumer/prosumer line in favor of enterprise healthcare cloud products.

## Best-practice takeaways
1. **"Select-and-Say" full text control** — reading the *actual on-screen text* (not just replaying what you said) lets users select, correct, and reformat previously-dictated content by voice, not just append new text. Exposed via a visible green/gray compatibility indicator on the DragonBar.
2. **Explicit "formal correction" vs. silent edit** — Dragon trains users that selecting wrong text and choosing from a ranked correction menu ("Choose 1," "Choose 2," "Add that to vocabulary") teaches the model, while manually retyping does not. This distinction is taught directly in onboarding copy.
3. **Written-form vs. spoken-form word entries** — letting a user specify that "PACU" is *written* one way but *pronounced* "pack-you" solves acronym/name mispronunciation cleanly, without waiting for enough real dictation samples to infer it.
4. **Auto-Texts / Step-by-Step Commands** — user-buildable macros: a spoken name inserts a pre-written text block (Auto-Text) or triggers a chained sequence of keystrokes/app-opens/waits (Step-by-Step Command, Dragon Medical One only) — a genuine no-code automation layer, not just a snippet expander.
5. **The Dictation Box as a universal fallback** — when the target app isn't natively compatible, text is never silently lost; it lands in a small staging window with an explicit "Transfer Text" step, and 4 different transfer mechanisms are offered because no single method works in every app.
6. **Anchoring dictation focus** — lock output to one window (with a visible lock-icon indicator) so the user can glance elsewhere without losing their place — solves multitasking-while-dictating.
7. **Formal Accuracy Tuning as a named, schedulable maintenance task** — bundling acoustic + language-model retraining into one wizard, explicitly recommended to run when the device is idle (CPU-heavy), rather than continuously in the background.
8. **Per-specialty vocabulary selection at session start** — a coarse but effective personalization lever (choose "Cardiology" vs. "General Medicine" vs. "Clinical Administration") that instantly re-weights recognition without per-word training.
9. **Printable one-to-two-page command cheat sheets per product/version** — a lightweight onboarding artifact distinct from the full manual.
10. **Explicit adaptation-phase framing** — telling users up front ("if you experience recognition errors in the first few minutes, keep dictating... this is particularly important if you speak with an accent") sets expectations instead of letting rocky first-run accuracy read as a broken product.

## Ideas Nasar Flow should steal or beat
1. **[steal] Written-vs-spoken word entry.** Let users add a custom word/phrase with a separate "how it's spelled" and "how I say it" field — directly useful for Singlish/Malay/Arabic proper nouns and code-switched terms that don't map cleanly to their phonetic spelling.
2. **[steal] A visible per-app "will this work well here" compatibility indicator**, à la Dragon's green/gray Full-Text-Control light — tell the user up front whether the current keyboard-extension target supports full select/correct, rather than letting them discover degraded behavior mid-dictation.
3. **[beat] Formal correction menu, but multilingual-aware.** Dragon's "Correct <text>" → ranked alternatives works within one language model. Nasar Flow should offer ranked alternatives that span code-switch boundaries (e.g., a Singlish/English/Malay blended utterance shows alternatives in the *actually intended* language mix, not force a monolingual guess) — something Dragon structurally cannot do.
4. **[beat] Auto-Texts, but voice-model-aware of dialect.** Dragon's Auto-Text macros are plain-text snippets triggered by an exact spoken name. Nasar Flow could let a macro trigger phrase itself be dialect-flexible (e.g., a Singlish phrasing and its formal English equivalent both fire the same macro), which Dragon's rigid single-name matching doesn't support.
5. **[steal] "No Space On/Off" style explicit mode toggles** for dictating identifiers (license plates, order numbers, etc.) without inter-word spaces — a small but genuinely useful, easily-copied command.
6. **[beat] Skip the mandatory spoken-punctuation tax.** Dragon requires speaking every comma/period explicitly with no inference layer — a real friction point competitors already solve with AI-inferred punctuation. Nasar Flow should keep (and market) automatic punctuation/formatting as a clear advantage over Dragon's "say every punctuation mark" model.
7. **[steal] The Dictation Box universal-fallback pattern** for the keyboard extension: when a target field can't reliably accept live-typed/pasted text, drop into a small staging buffer with an explicit "insert" action and multiple insertion strategies tried in order, rather than silently failing or losing dictated text.
8. **[beat] On-device-only, always — don't let cloud dependency creep in.** Dragon's own product line shows the tension: desktop Dragon is on-device (fast, private) while Anywhere/Medical One are cloud-only (subscription, latency, connectivity-dependent) — and the cloud products are exactly the ones now charging monthly/per-seat fees or getting discontinued. Nasar Flow's whisper.cpp on-device architecture is a durable structural advantage worth foregrounding against Dragon Anywhere's cloud dependency and its July 2026 sunset.
9. **[steal] Explicit adaptation-phase messaging on first run**, especially calling out accented speech — sets expectations and reduces "this app is bad" first-impression churn exactly the way Dragon Anywhere's docs do.
10. **[beat] Command-vs-dictation disambiguation.** Dragon's own users report the "typed 'scratch that' instead of executing it" failure mode. Nasar Flow should design (and test) explicit guardrails — e.g., a distinct trigger pattern or confirmation for destructive commands — to avoid the same class of bug, which is a known, long-standing, still-unresolved Dragon weakness.
