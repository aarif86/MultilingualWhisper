# MacWhisper

> Made by Jordi Bruin / Good Snooze (Netherlands, solo-indie-turned-small-team); a whisper.cpp/WhisperKit-based Mac transcription app that bolted on system-wide AI dictation as a side feature — the closest technical relative of Nasar Flow on desktop, though it is Mac-only, transcription-first (dictation is a secondary mode), and has no Singlish/Malay/Arabic code-switching design at all.

## Activation & capture UX
- Two distinct system-wide capture modes, easy to conflate: **Dictation** (types into whatever text field has focus, in place, replacing macOS's own dictation) and **Global** (a floating always-on-top Spotlight-style window that records, transcribes, and copies to clipboard for manual pasting) — both are Pro/subscription-gated and both use a user-configured keyboard shortcut with no fixed default published in docs (docs.macwhisper.com/article/14-how-to-use-the-dictation-feature; docs.macwhisper.com/article/16-global).
- Dictation is enabled either from the app's home screen ("Dictation" button, guided setup) or Settings > Dictation (docs.macwhisper.com/article/14-how-to-use-the-dictation-feature).
- Both **push-to-talk** (hold shortcut, release to finish — added v10.5) and **toggle mode** (press once to start/stop — added v10.6) are supported, user-selectable (release notes).
- Global has three dedicated toggles: **Auto Start** (begin recording the instant the Global window opens), **Auto Copy** (clipboard-copy on completion), **Always on Top** (default on) (docs.macwhisper.com/article/16-global).
- Live/streaming feedback was added late and incrementally: v11.7 added "Dictation streaming" (words appear as you speak, rather than only after you stop); v11.1 added Voice Activity Detection (VAD) for the WhisperKit engine (Pro); v13.11 added a separate **Realtime Captions** (Pro) feature using Deepgram for continuous live captioning distinct from dictation; v14.3 improved live transcription to stream "in order with readable paragraph grouping" (release notes). Third-party testing (2026) still describes live dictation as feeling "bolted on," with ~2.4s of silence before text appears and text landing all at once rather than flowing token-by-token — i.e. despite the streaming label, the UX is closer to chunked than truly incremental (getvoibe.com MacWhisper review).
- Audio is muted/paused during dictation recording so the user doesn't hear system sounds bleed in; v12.8 added explicit "mute audio during dictation" after Apple removed a pause API in macOS 15.4; v13.2.1 fixed dictation stalls specific to macOS 26.1-26.2; v14.8 fixed dictation "processing lockups."
- Dictation has its own **history** (last 50 items as of v10.5) that records the source app per dictation (v13.2) and now surfaces dictation *errors* inline in that history (recent release note).

## Text insertion
- Mechanism is described only at a high level in official docs ("lets you transcribe audio into any text field directly") — no explicit statement of accessibility-API vs paste vs keystroke-simulation. However the changelog is explicit that MacWhisper **simulates typing** rather than pasting: v9.3 "Rewrote the dictation typing engine," v9.12 "Improved 'typing' dictation output for Chrome, Firefox rich text fields," v10.8 "Dictation 10x faster for longer text" (i.e. they had to optimize a char-by-char typing engine for speed) — this strongly implies synthetic keystroke injection as the default path, with app-specific handling for browser rich-text editors.
- Known failure mode: **"For some apps that don't adhere to standard macOS development practices, MacWhisper may not be able to detect the textfield"** at all, so it can't tell whether it's safe to insert text (docs.macwhisper.com/article/44-dictation-not-working-in-specific-apps). No named app list is published (Help Scout explicitly declines to name culprits and asks users to email support@macwhisper.com per-case).
- Fallback: a manual override toggle, **Settings > Advanced > "Allow dictation everywhere,"** which disables the textfield-detection safety check and forces insertion regardless (same article). This is an honest admission that field-detection is heuristic and breaks silently in some apps — the override is a blunt "just try it anyway" escape hatch, not a smarter fallback.
- Global mode sidesteps the whole problem by never inserting directly — it only ever writes to the clipboard, leaving the paste action to the user.

## Accuracy & personalization
- **Find and Replace** (Settings, global) is MacWhisper's stand-in for a custom vocabulary/dictionary: paired "Original → Replacement" rules applied automatically to *all* new transcriptions and dictations, with two toggles — **"Case Sensitive"** and **"Only Replace Separate Words"** (word-boundary vs substring matching) (docs.macwhisper.com/article/37-find-and-replace-in-transcriptions). This is a static rewrite rule list, not a learned/adaptive dictionary — it does not auto-suggest corrections from user edits, and there's no per-contact-name import (no Contacts.app integration found in any crawled doc).
- v11.6 shipped a **"Dictation Word Dictionary"** — a separate mechanism specifically for dictation (vs the general Find/Replace) that auto-corrects misinterpreted terms using an AI prompt rather than a static string match (release notes) — this is closer to Wispr Flow's "teach Flow your words" dictionary concept, but is dictation-only and AI-prompt-driven rather than instant/deterministic.
- **App-Specific Dictation Prompts** (Settings > Dictation > App Specific Prompts, Pro): bind a different AI cleanup prompt per running application — e.g. auto-translate dictation to Spanish only in a specific chat app, generate code in a preferred language inside an editor, or enforce formal tone for an email client (docs.macwhisper.com/article/31-app-specific-dictation-prompts). Setup requires the target app to be actively running at configuration time to appear in the app picker.
- v12.0.1/v12.1.1 explicitly call out "improved spelling/grammar for dictations" and "improved AI dictation prompts" as ongoing, iterative accuracy work — accuracy improvements are being driven largely through prompt engineering on top of the ASR output, not through ASR fine-tuning.
- v12.5 added a dedicated **punctuation mode setting** for dictation (separate from AI cleanup) and v13.17 further refined "punctuation setting improvements for dictation," suggesting a non-AI, rule-based punctuation layer exists alongside the optional LLM pass.
- **Automatic Speaker Recognition** (Pro): local WhisperKit-based (M-series only) or cloud (ElevenLabs/Deepgram); accuracy improved ~60% in v12.16.1; this is a transcription feature, not dictation-relevant, but shows the same "local-first with cloud fallback" personalization pattern.

## Formatting & AI cleanup
- Core AI cleanup path is **user-supplied API key + user-authored or template prompt**, run against the raw dictation/transcript text: "You can also use ChatGPT prompts to process the dictated text and immediately perform AI features on it" — corrects spelling/grammar, translates, or expands informal notes into formal text (docs.macwhisper.com/article/14-how-to-use-the-dictation-feature). No default/bundled prompt text was found in any crawled doc — the setup guide explicitly stops at "enter a prompt description and the actual prompt text" without showing an example, i.e. **MacWhisper ships no canned prompt template for dictation cleanup**; users write their own from scratch, or copy examples from the community.
- **"Automatic spelling, punctuation and grammar improvement in dictation mode"** is listed as a distinct Pro feature on the Gumroad page, gated behind "requires AI Service to be setup" — confirming the cleanup pass is entirely dependent on an external LLM call, with no offline/local cleanup fallback.
- Auto **filler-word removal** ("ums, uhhs and other similar filler words") exists for transcription generally, and v11.4 added removal of asterisk-wrapped segments (LLM meta-commentary artifacts).
- **Assistant** (separate subscription-gated feature, works without a personal key): translation into 30+ languages, chat-with-transcript Q&A, auto-summary with highlights/action items, and cloud transcription — explicitly described as having "ongoing costs for us" that aren't covered by a one-time Pro purchase (docs.macwhisper.com/article/22-assistant). This is MacWhisper's only "no BYOK needed" AI path, and it's kept commercially separate from the lifetime license.
- No "raw vs polished" one-tap toggle is documented for dictation the way some competitors offer — cleanup is prompt-selection-based (pick which saved prompt to run, including "none").
- **Custom Export Formats** (v13.15 launch, v13.21 overhaul, Pro) let users define arbitrary output templates beyond the built-in txt/md/pdf/html/docx/csv/srt/vtt/Avid-.txt set, with per-format style settings — this is a batch/export-time formatting system, separate from dictation cleanup.

## Voice commands
- No dedicated in-dictation voice command grammar (no "delete that," "new line," "select word" spoken commands) was found anywhere in docs, release notes, or the Gumroad feature list — this is a real gap relative to command-mode competitors (e.g. Wispr Flow's Command Mode). MacWhisper's closest analog is text-level, not voice-level: the AI cleanup prompt can be written to interpret instructions embedded in speech (e.g. telling the LLM prompt to strip a phrase), but this is prompt-engineering by the user, not a built-in command vocabulary.
- The only "command"-like surface is macro-ish: App Specific Prompts act as a per-app mode switch, but it's triggered by which app has focus, not by anything spoken.

## Languages & multilingual
- 100+ languages for transcription (auto-detect or manual per-file selection), full list scraped from the Gumroad listing includes: English, Chinese, German, Spanish, Russian, Korean, French, Japanese, Portuguese, Turkish, Polish, Catalan, Dutch, **Arabic**, Swedish, Italian, Indonesian, Hindi, Finnish, Vietnamese, Hebrew, Ukrainian, Greek, **Malay**, Czech, Romanian, Danish, Hungarian, Tamil, Norwegian, Thai, Urdu, Croatian, Bulgarian, and dozens more down to Hawaiian, Lingala, Hausa, Bashkir, Javanese, Sundanese (goodsnooze.gumroad.com/l/macwhisper).
- Language selection is explicitly **per file / per session**, not per-word — there is no mid-utterance code-switching feature. The closest thing is v14.7's **"Match Keyboard Language"** dictation setting, which ties the dictation language to whichever keyboard input source is currently active on macOS — useful if a user manually switches keyboards mid-session, but still not automatic code-switching detection within one utterance.
- v14.8.1 added Google **Gemini 3.5 Transcribe** specifically advertising "76-language code-switching support" as a *cloud provider capability* — this is the one place "code-switching" appears verbatim in the crawled corpus, and it's Google's model capability being surfaced through MacWhisper's provider picker, not something Good Snooze engineered themselves.
- v12.18 added **Parakeet v3** with 25-language multilingual support (Bulgarian through Ukrainian, alphabetical range suggests a fixed list) — Parakeet v2/v3 started English-only (v12.12.2) and expanded multilingual later, mirroring the general industry pattern of English-first local models with multilingual bolted on in later releases.
- **Translation**: built-in Whisper-native translate-to-English (recommends Medium/Large models, docs admit "results will not be perfect"), plus a separate DeepL-API-key-based full-transcript/subtitle translation into 30+ languages via Assistant, plus live-caption translation via Apple's on-device Translation framework (v13.12).

## Privacy & data
- Default transcription is fully local/on-device: "All transcription is done on your device, no data leaves your machine. This makes MacWhisper a great app for sensitive audio such as interviews" (goodsnooze.gumroad.com/l/macwhisper) — this is the headline privacy claim and it's true for the default Whisper/WhisperKit/Parakeet path.
- Every AI-adjacent feature beyond that is explicitly opt-in and BYO-key: OpenAI, Anthropic, cloud transcription providers, etc. all require the user's own API key entered in Settings, which the app frames as keeping MacWhisper itself out of the data pipeline for those features. No SOC2/HIPAA/enterprise-compliance certification is claimed or mentioned anywhere crawled — no "zero data retention" language either, beyond the local-by-default architecture. Cloud partners each carry their own separate privacy exposure (e.g. Deepgram added an explicit **"Model Improvement Program" opt-out**, v14.7.1, implying Deepgram's default otherwise uses submitted audio for their own model training) — MacWhisper's docs do not editorialize on this, just add the toggle.
- ElevenLabs data-residency options (US/EU/India/Singapore endpoints) were added for Enterprise ElevenLabs accounts in v14.6 — notable that Singapore residency exists as an option in the ecosystem, though it's ElevenLabs' infrastructure, not Good Snooze's.
- Meeting recording (beta) requires screen-recording + microphone OS permissions and carries an explicit beta risk disclaimer ("there may be occasional issues or data loss") but no participant-notification feature is documented — MacWhisper records meeting audio without any built-in mechanism to notify other call participants, an ethical/legal gap left entirely to the user (docs.macwhisper.com/article/30-record-meetings).

## Changelog & velocity
- Extremely high release cadence for an indie app: full crawled history runs from v9.0 (dictation feature launch) to v14.8.1, with sub-point releases (e.g. 13.2 → 13.2.1 → 13.3...) shipping roughly every 1-3 weeks sustained over multiple years (macwhisper-site.vercel.app/release_notes.html).
- Last ~6 months (v13.13 → v14.8.1, reasoning from cadence) shipped: redesigned history screen, word-level timestamp export, watch-folder integrations, live translation captions via Apple Translation, Realtime Captions (Pro), Notion integration, free-tier access to large-v3-turbo (export still Pro-only), a full CLI with `--speakers` flag and batch/streaming support, an integrations framework (Make.com/n8n/Zapier/webhooks), five new cloud transcription providers (AssemblyAI, xAI/Grok, Rev AI, then Avalon/OpenRouter/Volcengine/Cartesia/Corti, then Cohere/Speechmatics), a redesigned "3 most-used models" model picker, "Match Keyboard Language" for dictation, and Gemini 3.5 Transcribe with 76-language code-switching. ## Blog / engineering insights
- No dedicated engineering/architecture blog post (latency benchmarks, model evaluation methodology, whitepaper) was found under macwhisper.com or docs.macwhisper.com in this crawl — Good Snooze's public engineering communication is almost entirely the terse release-notes changelog rather than long-form posts.
- The clearest technical acknowledgment of lineage is on the Gumroad page itself: *"Whisper was made by building on top of all the hard work from Georgi Gerganov, check out his Whisper implementation here: https://github.com/ggerganov/whisper.cpp"* — i.e. MacWhisper is explicitly and publicly whisper.cpp-based, the same open-source engine family Nasar Flow is built on, making it the most directly comparable technical architecture of any competitor researched.
- Model-tradeoff explanation is minimal and UI-embedded rather than written up: the only public guidance is the one-line "The Turbo model is a great choice for many Macs!" in the WhisperKit-switching doc — no published benchmark table, no WER numbers, no explicit large-v3-turbo-vs-distil-whisper comparison from Good Snooze themselves (third-party sites fill this gap, e.g. metawhisp.com's model-size explainer).

## User complaints (reviews, Reddit, HN, App Store)
- Mac App Store rating ~4.4/5 — generally positive, but concentrated praise is for file transcription, not dictation (getvoibe.com MacWhisper review).
- Recurring complaint: dictation is raw-output-first — "MacWhisper gives you raw Whisper output with no punctuation cleanup, no paragraph formatting, no typo corrections" unless the user sets up their own paid AI service, which is friction most casual users skip (third-party review synthesis; consistent with the docs confirming cleanup "requires AI Service to be setup").
- Live dictation UX complaint: ~2.4 seconds of dead air before text appears, no true token-by-token streaming, text arrives in one dump rather than flowing — despite the "streaming" changelog label (getvoibe.com MacWhisper review, 2026).
- Resource usage complaint: background process reported at ~1.1GB RAM; on 8GB Macs this compounds badly alongside a browser + productivity apps, causing noticeable slowdowns (same source).
- Hacker News sentiment (multiple threads, 2023-2025) is largely positive as a transcription tool ("godsend for transcribing," recommended repeatedly as the GUI-friendly Whisper wrapper), but a Sept-2025 thread shows newer local-dictation-only competitors positioning explicitly against MacWhisper's "long-running project with a lot more features" as bloat/complexity, and against reliability concerns serious enough that at least one dev cited MacWhisper's issues as motivation to "build a more stable alternative from the ground up" (news.ycombinator.com/item?id=45923930).
- Pricing-model confusion is its own recurring complaint theme: two nearly-identical products (Gumroad "MacWhisper" vs App Store "Whisper Transcription") at very different price points and feature sets (App Store version has NO dictation at all) causes real user confusion, documented at length by multiple third-party review sites and at least one Medium post titled bluntly *"MacWhisper's Pricing Is Confusing on Purpose."*
- Dictation reliability bugs recur across many point releases even in 2026 (dictation stalls on macOS 26.1-26.2 fixed in 13.2.1; "processing lockups" fixed in 14.8; keychain access issues fixed same release) — suggests dictation-as-a-feature is architecturally more fragile/OS-version-sensitive than the core file-transcription product.

## Best-practice takeaways
1. **Ship two clearly separated capture modes** — an in-place "type into the focused field" Dictation mode, and a separate "float above everything, copy to clipboard" Global mode — rather than forcing one UX to serve both "replace text as I talk" and "grab a quick note" use cases.
2. **Make the textfield-detection failure visible and give an escape hatch.** Rather than silently failing in unsupported apps, MacWhisper names the failure mode in docs and ships a blunt override toggle ("Allow dictation everywhere"). Users experiencing broken insertion have somewhere to go instead of assuming the app is simply broken.
3. **Let users bind different AI behavior per target app** (App Specific Dictation Prompts) — formal tone for Mail, code style for an IDE, auto-translate for a specific chat app. This is a genuinely good personalization axis that most competitors don't expose.
4. **A static Find/Replace rule table, with case-sensitivity and whole-word toggles, is a cheap and transparent substitute for a "smart" adaptive dictionary** — it's fully predictable, user-auditable, and works even fully offline with zero AI cost.
5. **Decouple the paid license from ongoing AI infra cost.** MacWhisper's lifetime purchase covers the local engine forever; anything with recurring third-party inference cost (Assistant cloud AI) is sold separately as a subscription. This keeps the one-time-purchase promise honest and sustainable.
6. **Chase ASR/LLM provider breadth aggressively and continuously** — nearly every release adds one more cloud ASR or LLM vendor. Even if none is deeply integrated, breadth itself is a marketed feature and a hedge against any single vendor's pricing/quality changes.
7. **Publish a real, dated, versioned changelog** with granular point releases — it visibly proves active maintenance and gives support/community something concrete to reference ("fixed in 14.8").

## Ideas Nasar Flow should steal or beat
1. **[steal] App-specific AI prompt binding.** Nasar Flow should let a user set different cleanup behavior per target app (e.g. more formal English cleanup in Mail/Outlook, preserve Singlish/code-switched phrasing verbatim in WhatsApp/Telegram, no cleanup at all in a code editor). MacWhisper proves this is implementable as a simple "+ app → pick prompt" list, no deep OS integration required beyond detecting the frontmost app.
2. **[beat] Don't make cleanup fully dependent on an external LLM call.** MacWhisper's "automatic spelling, punctuation, grammar improvement" only exists if the user sets up a paid AI service — the honest default experience is raw, unpunctuated Whisper output. Nasar Flow's offline whisper.cpp foundation is the differentiator here: ship a genuinely useful **on-device** rule-based punctuation/formatting pass (MacWhisper already proves this is worth a dedicated non-AI "punctuation mode" toggle) so code-switching users get clean text even with zero network and zero API key — something MacWhisper structurally cannot promise for its cleanup layer.
3. **[beat] Solve code-switching as a first-class feature, not a footnote.** In the entire MacWhisper corpus, "code-switching" appears exactly once — as a bullet point about Google's Gemini 3.5 Transcribe cloud model, i.e. someone else's model capability surfaced through a picker. MacWhisper's own language handling is strictly per-session/per-file, with "Match Keyboard Language" as its only nod to mid-use flexibility. Nasar Flow's entire premise (Singlish/Malay/Arabic mixed in one utterance) is a real, structural product gap for every competitor researched so far — this should be marketed explicitly as "the dictation app that doesn't force you to pick one language per sentence."
4. **[beat] Fix the textfield-detection problem architecturally, not just with an override.** MacWhisper's "may not detect the textfield" failure plus a blunt "allow everywhere" toggle is an honest but weak mitigation. Nasar Flow's system keyboard extension (rather than an accessibility-API-guessing overlay app) sidesteps this entire class of bug by construction — this is a genuine architectural advantage worth foregrounding against MacWhisper/Superwhisper-style Mac overlay apps, since a keyboard extension always has a text field by definition.
5. **[steal] Ship a real, adaptive per-user Word Dictionary distinct from the static global Find/Replace**, the way MacWhisper's v11.6 "Dictation Word Dictionary" is a separate, AI-assisted correction list from its general Find/Replace. For Nasar Flow this matters even more given proper nouns and code-switched loanwords (e.g. Malay honorifics, Arabic religious terms) that generic multilingual Whisper models routinely mangle.
6. **[steal] Publish a visible, dated changelog at high cadence**, even for a small team — MacWhisper's granular point-release changelog is a low-cost trust signal ("this bug you hit was fixed in the release two weeks ago") that Nasar Flow should adopt as a public page, not just internal release notes.
7. **[beat] Add participant-notification for any meeting/call recording feature**, unlike MacWhisper's beta meeting recorder, which has zero mechanism to inform other call participants they're being recorded — a real ethical/legal exposure Nasar Flow can close by design if it ever ships meeting capture, especially given Singapore's PDPA consent expectations.
8. **[beat] Streaming dictation that actually streams.** Reviewers explicitly call out MacWhisper's "streaming" label as misleading — ~2.4s dead air, then a single text dump. Given Nasar Flow's on-device model, true low-latency incremental partial-result display (even coarse word-by-word) as speech is captured would be a clearly superior, verifiable UX claim against MacWhisper's actual (reviewed) behavior.
