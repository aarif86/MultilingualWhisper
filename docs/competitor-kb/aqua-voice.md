# Aqua Voice

> Made by Aqua (Y Combinator W24); a cloud-based, proprietary-ASR ("Avalon") dictation app for Mac, Windows, and iPhone aimed at knowledge workers, developers, and AI-prompt-heavy users who want fast, accurate, context-aware voice-to-text in any text box.

## Facts
- **Maker / founded / funding:** Aqua, Inc. (aquavoice.com / withaqua.com). Y Combinator W24 batch company. Co-founder Finnian Brown is dyslexic and has used dictation software since 6th grade (started on Dragon Dictation, set up by his father) — cited as the founding motivation: "Dictation has remained surprisingly rigid in the era of LLMs." (ycombinator.com/launches/Kjl-aqua-voice-voice-only-text-editor)
- **Platforms:** macOS (Apple Silicon + Intel), Windows 10/11, iOS (launched April 2026 as a full AI voice keyboard on Avalon 1.5); no Android, no Linux. Cloud API also available for developers (Avalon API). All cloud-only — requires an internet connection, no offline/on-device mode. (aquavoice.com, aquavoice.com/windows, aquavoice.com/mac, aquavoice.com/blog/aqua-voice-for-ios)
- **Pricing:** Starter (free) — 1,000 words, no card required. Pro — $8/mo billed annually ($10/mo monthly); unlimited words, Custom Instructions, expanded Custom Dictionary. Max — $24/mo: everything in Pro + Realtime Mode + "Send it" voice command + early feature access. Team — $12/user/mo (2-9 seats): centralized billing, team-wide settings, Privacy Mode enforcement. Business — custom pricing (10+ seats): SSO/SAML + SCIM, advanced reporting, zero data retention, team dictionaries. Student discount: 70% off Pro (~$3/mo annual, $2.40/mo when discounted+annual per one source). Avalon API (developer): $0.39/hour of audio, billed per-second with a 10-second minimum, no seat fees. (aquavoice.com, aquavoice.com/info/faq, aquavoice.com/windows, aquavoice.com/avalon-api)
- **Engine:** 100% cloud-based. Proprietary ASR described at YC launch as using "an MoE [Mixture-of-Experts] transcription architecture" combining real-time audio processing with LLMs to understand user intent, achieving lower WER than Whisper-large-v3 in real time and supporting arbitrary voice commands with no fixed command vocabulary (ycombinator.com/launches/Kjl-aqua-voice-voice-only-text-editor). Shipped as **Avalon** (launched Aug 22, 2025, replacing the earlier Whisper-based pipeline) and now **Avalon 1.5**, described as Aqua's "first natively multilingual model" — 5.55% average WER on OpenASR (down from 6.24% for Avalon 1), reportedly winning 76% of head-to-head comparisons vs. ElevenLabs Scribe V2 while being "more than twice as fast" (aquavoice.com/blog/aqua-voice-for-ios). Trained specifically on "prompt-style speech, code, and email" rather than audiobooks/meetings — their stated rationale: "People speak very differently when they are writing a prompt for Claude Code than when they're talking to a colleague, expecting a meeting transcript at the end." (aquavoice.com/blog/introducing-avalon) LLM-style post-processing runs on top of raw transcription to strip filler, fix grammar, and reformat for the destination app (aquavoice.com/info/faq). No stated on-device/offline option anywhere.
- **Languages:** 49 languages (incl. Arabic, English, French, German, Japanese, Korean, Mandarin, Cantonese, Portuguese, Russian, Spanish, Tamil, Thai, Turkish, Ukrainian, Vietnamese, Welsh, Bengali). Auto-detect switches languages mid-speech. (aquavoice.com/info/faq)

## Activation & capture UX
Push-to-talk model: **hold a key, talk, release** ("hold the key, talk, release" — aquavoice.com/mac). On Mac/Windows the documented default is **hold Spacebar** to activate dictation, release to insert (per homepage and Windows page: "hold spacebar to dictate; release to insert text" — likely a configurable/global activation key rather than literally hijacking the OS spacebar everywhere, but that's how the marketing pages describe it). The Cursor-integration blog post separately names the **default push-to-talk hotkey as Fn**, operating at the OS level rather than through any IDE extension — one hotkey covers Cursor's Chat, Agents window, inline edit (Cmd+K), and the integrated terminal simultaneously (aquavoice.com/blog/best-speech-to-text-for-cursor). Multiple activation keys can be configured (guide index references "Multiple activation keys setup"). Max plan adds a **hands-free Realtime Mode**, where text streams in live as you speak rather than only appearing on release, plus mouse-button binding to start dictation, go hands-free, or paste the last transcript without touching the keyboard (changelog v0.18.6, July 30 2026).
On **iOS**, Aqua ships as "Aqua Keyboard" — the blog frames it as voice input "anywhere" via keyboard-extension-style access, built on Avalon 1.5 (aquavoice.com/blog/aqua-voice-for-ios); exact mobile activation gesture and permission flow were not detailed on the crawled page.

## Text insertion
Uses the **macOS Accessibility API** to type/inject text directly into the focused field: "if you can place a cursor in it, you can dictate into it" (aquavoice.com/mac) — no per-app setup required, works in Terminal/iTerm/Ghostty, browsers, native apps, spreadsheets (explicit "spreadsheet cell insertion" support per FAQ). Requires the user to grant **Microphone** + **Accessibility** permissions on first run (Mac). Windows presumably uses an equivalent OS-level input-injection approach (not detailed on the Windows page). No mention of a fallback-to-clipboard-paste behavior or a list of known-broken apps in the crawled pages.

## Accuracy & personalization
- **Custom Dictionary**: up to 800 entries (per FAQ), syncs across desktop and mobile so custom names/brands/jargon are recognized everywhere. Bulk-add terms feature shipped June 3 2026 (changelog v0.14.21).
- **Custom Instructions** (Pro+): user-written style rules that steer post-processing output.
- **Context-aware transcription**: Aqua reads screen/app context to decide formatting and vocabulary — e.g. recognizing it's in VS Code vs. Slack vs. Gmail and adjusting accordingly (aquavoice.com/info/faq, aquavoice.com/use-cases).
- **Domain vocabulary out of the box**: Avalon is explicitly trained to recognize AI/dev terms like "GPT-4o," "kubectl," "PyTorch," library/framework/CLI names — this is a training-data choice, not just a dictionary lookup (aquavoice.com, aquavoice.com/blog/best-speech-to-text-for-cursor).
- **Accuracy claims**: 97.3% on their own "AISpeak" benchmark; AISpeak-10 97.4%, AISpeak-50 97.5%, AISpeak-500 95.8% (vs. Whisper Large v3 65.1% and NVIDIA Canary 1B 51.5% on AISpeak-10) (aquavoice.com/blog/introducing-avalon). Word-error rates cited elsewhere: 0.9% (emails), 1.0% (technical reports), 0.7% (book dictation) (aquavoice.com/info/faq). On OpenASR leaderboard: 6.24% average WER, #1 among proprietary models, #6 overall at Oct 2025 debut; beats Whisper Large v3 on 7/8 standard splits and ElevenLabs Scribe on 6/8 (aquavoice.com/blog/introducing-avalon).
- Independent check cited on their own site: 9to5Mac found Apple Dictation made 17 errors vs. Aqua's 1 error on the same passage — reading the opening of Steve Jobs' Stanford commencement speech, simultaneously on two Macs, using built-in mics; Aqua's single error was "was born" instead of "popped out." 9to5Mac also noted Aqua auto-inserted paragraph breaks where Apple Dictation produced one undifferentiated block, and called it "the best dictation app I've ever used" — while flagging privacy skepticism about a smaller vendor handling sensitive/contextual content, and reporting occasional connectivity errors and one ~20-minute server outage during testing (9to5mac.com/2025/08/15/aqua-voice-shows-just-how-good-mac-dictation-could-be-if-apple-just-tried/).
- Third-party reviewers caution the headline 97.3%/97.4% AISpeak numbers are a **self-reported, vendor-created benchmark**, not an independent test — "the 97.4% figure comes from AISpeak-10, a benchmark Aqua created itself" (getvoibe.com/resources/aqua-voice-review/). Avalon's independently-verifiable standing is the public OpenASR leaderboard placement instead.
- Cursor-integration blog post lists concrete transcribed technical terms as evidence of domain accuracy: `getServerSideProps`, `tRPC`, `Tailwind`, `Supabase`, `npx` transcribed correctly (aquavoice.com/blog/best-speech-to-text-for-cursor). Also describes a **"Deep Context"** feature that "reads what is on screen" to bias transcription toward identifiers present in the active buffer/window — a concrete screen-context injection mechanism, distinct from just app-detection.

## Formatting & AI cleanup
Post-processing pipeline explicitly "strips filler, fixes grammar, and formats for the destination app" (aquavoice.com/info/faq). App-aware output: professional structure for emails, thread-appropriate tone for Slack, casual style for iMessage/WhatsApp/Messenger, code-syntax-appropriate output for dev tools (aquavoice.com homepage, /use-cases). "Writing Styles" setting lets users pick tone/format presets (professional vs. casual). **Edit Mode** (shipped July 20 2026, v0.17.0): select existing text anywhere, hold the activation key and speak the change — handles typo fixes, translations, reformatting, and number cleanup as in-place rewrites, i.e. a voice-driven rewrite/command mode on arbitrary selected text.

## Voice commands
- **"Send it"** (Max plan only, shipped July 26 2026 v0.18.0): ends hands-free/Realtime dictation and auto-submits the message — "Aqua removes the command from the transcript, inserts your message, and submits it automatically." Supports natural command variants in English, Japanese, Spanish, French, German, and Russian (per WebSearch summary of changelog).
- Users can configure which key finalizes "Send It" — Enter, Cmd+Enter (Mac), Ctrl+Enter (Windows) — or choose "Paste Only" to review before submitting (changelog v0.18.5, July 29 2026).
- Edit Mode commands are natural-language ("fix the typo," "translate this," etc.) rather than a fixed command grammar — no rigid phrase list like "delete that" / "new line" was found in the crawled pages. Specific mobile Voice Edit Mode example phrases from the iOS blog post: **"Remove filler words, this is a slack message,"** **"Translate this to Japanese,"** **"Make this title case"** (aquavoice.com/blog/aqua-voice-for-ios) — confirming the command style is open-ended natural language, LLM-interpreted, rather than a fixed grammar/keyword list.
- YC launch materials frame this as a deliberate design principle: users should be able to "execute arbitrary voice commands" with "no specialized command vocabulary needed" (ycombinator.com/launches/Kjl-aqua-voice-voice-only-text-editor) — i.e., Aqua's philosophy is explicitly anti-fixed-phrase, unlike traditional dictation tools (Dragon-style "select word," "scratch that") that require memorized commands.

## Privacy & data
- **Privacy Mode**: an option so "nothing [is] stored on servers" for transcripts (aquavoice.com homepage).
- **Transcript History**: past transcriptions are retained by default (with privacy controls to disable), accessible via a History feature.
- **Encryption/transport**: TLS-encrypted HTTPS and WebSockets over port 443 (aquavoice.com/info/faq).
- **Certification**: SOC 2 Type II certified; trust/security details published via Vanta trust portal (app.vanta.com/withaqua.com/trust/...).
- **Enterprise**: Business tier offers **zero data retention**, SSO/SAML + SCIM, team dictionaries, advanced reporting.
- **Training opt-in**: audio/transcripts are NOT used for model training unless the user explicitly opts in; otherwise processing is described as ephemeral (aquavoice.com/blog/introducing-avalon).
- No on-device/offline mode exists at all — this is a core architectural difference vs. Nasar Flow (see Ideas section).

## User complaints (reviews, Reddit, HN, App Store)
- **Cloud dependency / privacy is the #1 recurring objection.** Reviewers frame it bluntly: it "runs entirely in the cloud, sends every phrase you speak to its servers, and bills you every month" (softorbits.net-derived summary); getvoibe.com adds that "audio always leaves your machine." Compounding this: **Privacy Mode is OFF by default for individual accounts** — "Without it, transcripts may be stored" (spokenly.app/blog/aqua-voice-review) — and the privacy policy is described as "ambiguous on AI training" (getvoibe.com).
- **No offline mode, no Android, no Linux support** are repeatedly named limitations across every third-party review crawled.
- **No HIPAA compliance** — spokenly.app flags this explicitly as making Aqua unsuitable for regulated/medical workflows despite SOC 2 Type II.
- **Background-audio sensitivity**: reviewers report it transcribes nearby conversations/ambient noise in shared spaces (spokenly.app).
- **Limited free tier with no time-boxed trial**: 1,000 words lifetime (~7-8 minutes of speech), one-time only, no recurring free allowance — called out as thin by both spokenly.app and getvoibe.com.
- **Subscription-only, no lifetime option**: getvoibe.com calculates $8/mo compounds to $288 over 3 years, unfavorably contrasted with a competitor's $149 lifetime price.
- **Occasional reliability bugs**: rare clipboard/paste failures on long text blocks, infrequent crashes, connectivity errors requiring app restarts, and at least one ~20-minute server outage observed by a 9to5Mac reviewer during testing.
- **Churn anecdote**: one reviewer reported they "deleted after 3-4 months and switched back to VoiceInk" (open-source/offline tool), citing the cloud/privacy tradeoff (spokenly.app-derived summary).
- **Reddit discussion volume** (r/macapps, r/productivity) is noticeably thinner than for Wispr Flow or Superwhisper per secondary sources — smaller community/mindshare than the top two competitors, making broad sentiment harder to verify independently.
- Despite the above, praise is consistent and strong: Product Hunt shows a **5.0/5 rating across 15 reviews**, with quotes like "It's the fastest and has the best accuracy of any of the ones that I've tried," a long-time Dragon Dictate user calling it "the best voice-to-text solution I've ever had the pleasure of using," and "It's become the de facto way that I write on my computer" (producthunt.com/products/aqua). getvoibe.com cites a Product Hunt user who "nearly doubled my personal output daily." Accessibility users (e.g., motor-impaired/dyslexic) specifically praise predictable behavior and custom-dictionary support for specialized vocabulary.

## Best-practice takeaways
1. **Push-to-talk with a single global hold-key** ("hold the key, talk, release") — zero-friction activation with no menu hunting, works identically across every app because insertion is done via the OS accessibility layer, not app-specific integrations.
2. **App-aware output formatting** — detecting the destination app/context and changing tone/structure automatically (email vs. Slack vs. terminal vs. code) rather than one-size-fits-all transcription.
3. **Domain-specific training data as the accuracy lever** — Avalon's edge comes from training on prompt/code/email speech patterns specifically, not just a bigger general model; published, checkable benchmarks (AISpeak, OpenASR) as a trust/marketing device.
4. **Custom Dictionary that syncs across devices**, with a bulk-add path — reduces per-device re-training friction for names/jargon.
5. **Edit Mode**: reusing the exact same activation gesture (hold key + speak) for *rewriting already-inserted text* rather than only for fresh dictation — one mental model covers both "write" and "fix."
6. **"Send It" hands-free submit**, localized to multiple languages, with a user-configurable finish key and a safety "Paste Only" review option — voice command design that still lets the cautious user opt out of full automation.
7. **A public, always-linked status page** (status.aquavoice.com) — since the whole product is cloud-dependent, uptime transparency is treated as core trust infrastructure, not an afterthought.
8. **Tight, dated, versioned changelog** shipped roughly weekly — builds a visible sense of momentum and lets support point users to "fixed in v0.18.5" type answers.
9. **Enterprise trust signals bundled early**: SOC 2 Type II + a public Vanta trust page + a "zero data retention" tier, even for a small YC startup — de-risks enterprise sales conversations before they start.
10. **Anti-fixed-vocabulary design philosophy**: explicitly markets "no specialized command vocabulary needed" — voice commands are open natural language interpreted by an LLM layer, not a memorized phrase list (Dragon-style). Lowers the learning curve versus traditional dictation tools.
11. **"Deep Context" screen-reading for accuracy**: biasing transcription toward identifiers/library names literally visible in the active window/buffer, not just knowing which app has focus — a more granular context signal than app-detection alone.
12. **Self-published, checkable benchmarks paired with an honest limitations page** (aquavoice.com/vs): naming exactly where they lose (offline, Linux/Android, fully local processing) builds credibility precisely because they don't oversell the cloud tradeoff.

## Ideas Nasar Flow should steal or beat
1. [steal] **App-aware / context-aware formatting.** Aqua reads what app/field you're dictating into and adjusts tone and structure. Nasar Flow ships no LLM cleanup yet — even a lightweight, on-device rule-based formatter (e.g. detect keyboard-extension host app or just punctuation-normalize differently for message vs. notes) would close a visible gap cheaply.
2. [beat] **Cloud vs. on-device privacy story.** Aqua's whole architecture sends every utterance to their servers — their own reviewers call this out as the top complaint. Nasar Flow's offline whisper.cpp pipeline is the opposite and should be marketed explicitly as "zero data leaves your phone," directly countering Aqua's biggest weakness rather than treating on-device as just a technical detail.
3. [steal] **Custom Dictionary with cross-device sync.** Aqua's 800-entry synced dictionary handles names/jargon; Nasar Flow has no shipped custom vocabulary. Given Nasar Flow's Singlish/Malay/Arabic code-switching use case, a small on-device custom-term list (family names, dialect words, brand names) would directly attack a known whisper.cpp weak point — proper nouns and code-switched vocabulary.
4. [beat] **"Send It" hands-free voice command, localized.** Aqua ships this only for Max-tier users and only as an auto-submit command. Nasar Flow has zero voice commands today. Given the multilingual audience, even a minimal "hantar" / "send" / إرسال style command (localized to Singlish/Malay/Arabic) would leapfrog Aqua's English-Japanese-Spanish-French-German-Russian set by directly targeting the underserved code-switching market Aqua doesn't specialize in.
5. [steal] **Edit Mode pattern (hold key + speak the fix on selected text).** Reusing the same activation gesture for both dictation and correction is a clean, learnable interaction. Nasar Flow's manual copy/paste insertion on iOS is currently the weakest link in the pipeline; a similar "select + speak the fix" pattern (even if implemented as a secondary text-selection + re-transcribe flow rather than true accessibility-API in-place edit) would reduce reliance on manual re-typing corrections.
6. [beat] **Accessibility-API text insertion vs. manual copy/paste.** Aqua inserts directly into any focused field via macOS Accessibility API — "no per-app setup." Nasar Flow's iOS insertion today is manual copy/paste, a materially worse UX. Investigating iOS equivalents (custom keyboard extension's own text-insertion, or UITextInput-level injection where entitlements allow) to reach "type as you dictate" parity is a concrete, high-value engineering target.
7. [beat] **Published, checkable accuracy benchmarks.** Aqua built its own "AISpeak" benchmark and publishes numbers against Whisper/Canary/ElevenLabs to build trust. Nasar Flow could publish its own Singlish/Malay/Arabic code-switching benchmark (a domain none of these competitors target) — an area where whisper.cpp fine-tuned/tuned for local dialect could plausibly beat Avalon, ElevenLabs, and Whisper out of the box, and where "we tested this on real Singlish, they didn't" is a differentiated, defensible claim.
8. [steal] **Public status page as trust infrastructure** — even though Nasar Flow is offline-first and thus less exposed to this failure mode, a simple status/known-issues page for the keyboard extension and TestFlight builds would mirror this practice and reduce support load.
9. [beat] **Multilingual auto-detect that switches mid-speech.** Aqua claims 49-language auto-detect but does not specifically market intra-utterance code-switching (mixing two languages in the same sentence) — which is exactly Nasar Flow's core design target (Singlish/Malay/Arabic code-switching). This is Nasar Flow's most defensible wedge: market and benchmark code-switching accuracy explicitly, since Aqua's marketing only ever discusses language-to-language switching, not mixed-language utterances.
10. [beat] **Privacy Mode default and data-retention ambiguity.** Aqua's individual-tier Privacy Mode is OFF by default and its training-data policy reads as ambiguous to reviewers — a repeatedly cited trust gap. Nasar Flow, being fully offline, should make "on-device by default, always, no toggle needed" a headline claim rather than an opt-in setting — beating Aqua on the exact axis its own users complain about.
11. [steal] **Anti-fixed-vocabulary voice command philosophy.** Aqua deliberately avoids Dragon-style memorized command phrases, using open natural-language commands instead ("remove filler words, this is a slack message"). If/when Nasar Flow adds any voice commands, follow this same principle — free-form LLM-interpreted intent rather than a rigid phrase table — since Singlish/Malay/Arabic speakers code-switch even within commands, and a fixed English phrase list would immediately break for them.
12. [beat] **"Deep Context" screen-reading for vocabulary bias.** Aqua biases transcription toward on-screen identifiers for coding contexts. Nasar Flow's target domain (dialect/code-switched speech) doesn't have an equivalent "screen text" signal to lean on today, but a comparable idea — biasing decoding toward a small on-device contact/name list or recently-typed words in the same text field — is a lower-effort on-device analog worth prototyping, and one Aqua can't easily do for non-English/code contexts.
