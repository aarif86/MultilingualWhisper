# Wispr Flow

> Made by Wispr AI (San Francisco, founded 2021 by Tanay Kothari and Sahaj Garg); cloud-only AI voice dictation app for Mac, Windows, iPhone, and Android that turns speech into polished, formatted text in any app. Direct competitor to Nasar Flow in category, but structurally different: 100% cloud-dependent (no offline mode), English/Western-language-first, and explicitly documents that it does NOT handle mid-sentence code-switching well — the opposite of Nasar Flow's Singlish/Malay/Arabic focus.

## Facts
- **Maker / founded / funding:** Wispr AI, founded 2021 by Tanay Kothari and Sahaj Garg (en.wikipedia.org/wiki/Wispr_Flow). Originally built a non-invasive wearable for touchless phone control; after ~3 years concluded contemporary AI wasn't sufficient for that hardware vision and pivoted to software, shipping **Wispr Flow in 2024** using speech tech developed for the abandoned wearable (en.wikipedia.org/wiki/Wispr_Flow). Original public launch: "Show HN: Wispr Flow – A new voice dictation experience," Oct 8, 2024, with a Steve Wozniak demo and endorsement from Rahul Vohra of Superhuman (news.ycombinator.com/item?id=41696153). Funding: Series A $30M (June 2025, led by Menlo Ventures) → Series A extension $25M (Nov 2025, led by Notable Capital) → Series B $280M (Aug 2026, led by Menlo Ventures) = **$335M+ total raised**; early investors Neo, MVP Ventures, AIX Ventures (en.wikipedia.org/wiki/Wispr_Flow). Reported metrics as of mid-2025: >50% monthly user growth, ~80% six-month active-user retention, ~19% payment conversion, ~$3.8M revenue (Jul 2024–Jul 2025) (same source — unverified third-party/Wikipedia figures, flag for confirmation).
- **Platforms:** Mac, Windows, iPhone (iOS), Android (wisprflow.ai; docs.wisprflow.ai/articles/2772472373-what-is-flow). Notetaker (meeting-notes product) launched Mac-only Aug 5, 2026, Windows "in development" (wisprflow.ai/post/wispr-flow-notetaker).
- **Pricing** (wisprflow.ai/pricing):
  - **Free** — $0/mo. 2,000 words/week on desktop; 1,000 words/week on iPhone; one third-party-summarized source says "unlimited" on Android (unconfirmed, flag for verification). Includes basic dictation, Notetaker access, speaker ID, MCP integration.
  - **Pro** — $15/user/month billed monthly, or **$12/user/month billed annually** (20% annual discount). Unlimited dictation, Command Mode unlocked, advanced AI models, early feature access, prioritized support, centralized billing, team usage analytics.
  - **Growth/Enterprise** — from $23/user/month monthly, from **$18/user/month annually**. Everything in Pro plus SSO/SAML, directory provisioning, org-wide HIPAA enforcement, audit logs, dedicated customer success manager, card/invoice/PO billing.
  - Students/educators: 50% off Pro. Nonprofits: discounted Pro pricing. No credit card required for free tier. 14-day free trial referenced repeatedly in third-party reviews and the cancellation policy (getvoibe.com summary); "cancel anytime," refunds after the 14-day trial only where legally required.
- **Engine:** Cloud-only — **no offline mode exists**. Audio is captured locally on hotkey press, streamed to the cloud, transcribed remotely, and pasted back on release (docs.wisprflow.ai/articles/2772472373-what-is-flow). Pipeline: capture mic → voice-activity detection → ASR engine (historically OpenAI Whisper; a 2026 research post says newer per-language options include "Scribe" and "Gemini") → LLM post-processing pass that strips filler words, fixes punctuation/formatting, and personalizes → paste (wisprflow.ai/research/supporting-languages). Third-party (not first-party) technical claims, flagged unverified: end-to-end latency "under 700ms at p99" via Baseten on AWS us-east-1, though users report the real round-trip feels like 1–2 seconds; Electron-based desktop app idles at ~800MB RAM / ~8% CPU continuously (getvoibe.com/resources/openai-whisper-vs-wispr-flow).
- **Languages:** "100+" marketed; Wikipedia cites 104. Official tiering: **7 "premier" languages** with English-level performance — French, German, Hindi, Italian, Portuguese, Spanish, Thai — plus **75+ additional languages** (Arabic, Cantonese, Dutch, Hebrew, Indonesian, Japanese, Korean, Mandarin, Polish, Russian, Swedish, Turkish, Ukrainian, Vietnamese, etc.) (wisprflow.ai/research/supporting-languages). **Auto-detection is per-session, not per-word**: "Flow picks a language at the start of each dictation session and transcribes the whole segment in that language" — genuine mid-sentence code-switching is explicitly NOT supported, and Chinese–English is named as the hardest case (docs.wisprflow.ai/articles/3191899797-use-flow-with-multiple-languages).

## Activation & capture UX
- **Push-to-talk (default hotkeys):** Mac: `Fn` (falls back to `Ctrl+Opt` if no Apple Fn key detected); Windows: `Ctrl+Win`. Recommended alternates: `Ctrl+Opt`/`Opt+Cmd`, or mouse buttons `Mouse4`/`Mouse5`/Middle Click (docs.wisprflow.ai/articles/2612050838).
- **Hands-free mode (continuous listening, no key held):** Mac `Fn+Space` (or `Ctrl+Opt+Space`); Windows `Ctrl+Win+Space`. Double-tapping the push-to-talk shortcut also locks into hands-free. Stops via the same shortcut, clicking the stop icon, or `Esc` (docs.wisprflow.ai/articles/6391241694-use-flow-hands-free).
- **Command Mode (separate shortcut from dictation):** Mac with Fn key: `Fn+Ctrl`; Mac without Fn: `Cmd+Ctrl+Option`; Windows: `Ctrl+Win+Alt`. Press-hold-speak-release pattern; double-press activates hands-free instantly; triple-press dismisses; `Esc`/`Backspace` cancels (docs.wisprflow.ai/articles/4816967992-how-to-use-command-mode).
- **Cancel:** `Esc` on both platforms.
- **Other bindings:** Paste last transcript — Mac `Cmd+Ctrl+V` / Windows `Shift+Alt+Z`. Copy last transcript — Mac `Cmd+Ctrl+C` / Windows `Shift+Alt+X`. Open Scratchpad — Mac `Opt+S` / Windows `Win+Alt+S`. Notetaker — Mac `Opt+M` (docs.wisprflow.ai/articles/2612050838).
- **Customization:** All shortcuts configurable in **Settings → General → Shortcuts** (renamed "Flow Hub" in some docs); up to 4 shortcuts per action, max 3 keys each; supports mouse buttons (Mouse 4–10, middle click) and function keys F1–F20 (Mac) / F1–F24 (Windows); validated live against OS-reserved combos and existing bindings; single letters/numbers/punctuation alone cannot be bound; reserved OS shortcuts (e.g. `Cmd+C`) are blocked (docs.wisprflow.ai/articles/2612050838, .../4816967992).
- **Session limits:** Desktop dictation capped at **20 minutes** (warning at 19 min) — this is a 4x increase from a prior 5-minute cap, shipped March 31, 2026 (wisprflow.ai/whats-new). Android hands-free capped at 5 minutes (warning at 4 min). iOS hands-free has no stated limit in docs, though third-party App Store review analysis reports practical failures around 7–8 minutes.
- **Mobile activation without opening the app:** iOS — Action Button (iPhone 15 Pro+, guided setup with demo video), Back Tap (double/triple tap, Settings → Accessibility → Touch → Back Tap), or Control Center widgets (a recording-toggle widget and a "Flow Notes" waveform-mic widget) (docs.wisprflow.ai/articles/1986921789). Android — **"Flow Bubble,"** a floating overlay that appears on tapping a text field; supports both tap-to-dictate and hold-to-dictate, confirmed with a checkmark (docs.wisprflow.ai/articles/6409258247-starting-your-first-dictation).
- **Visual feedback:** **"Flow Bar"** on desktop, **"Flow Bubble"** on Android — persistent small overlay UI showing recording state; both have dedicated troubleshooting docs for "not appearing/disappearing" issues, implying they are a recurring source of confusion (docs.wisprflow.ai/articles/5002934560, referenced via search).
- **Permissions required to activate at all:** microphone (all platforms); accessibility (Mac, Windows, Android); "Allow Full Access" for the iOS keyboard extension; overlay/appearance permission (Android) (docs.wisprflow.ai/articles/3152211871-setup-guide).

## Text insertion
- Desktop/Android rely on OS accessibility APIs to detect the focused text field and insert text (not a generic OS-level "type" simulation only); when Flow **cannot verify** the text landed correctly (very long documents, slow-rendering apps, insertion taking too long), it falls back to **copying the transcript to the clipboard and showing a manual "Paste" button on the Flow Bubble/Bar** rather than silently failing (docs.wisprflow.ai troubleshooting pages, per search summary).
- iOS uses a genuine **third-party keyboard extension** ("Flow Keyboard") requiring "Allow Full Access," switched to via the globe key on any text field (docs.wisprflow.ai/articles/1986921789).
- **Documented known-broken scenarios:**
  - **macOS Secure Keyboard Entry / Secure Event Input** — often silently enabled by Terminal/iTerm2, a background app with a focused password field, or **Slack** — blocks Flow's global hotkeys system-wide until the offending app is quit or the field loses focus (docs.wisprflow.ai/articles/8841649969, per search summary).
  - **Windows Terminal** does not register a held `Ctrl` for Flow's hotkey even though it works elsewhere (per search of GitHub issue microsoft/terminal#19725 and docs cross-reference).
  - **Non-QWERTY keyboard layouts** (Dvorak, Colemak, non-Latin layouts) cause Flow to fail to detect text fields or insert incorrectly, sometimes with an error chime — this is a documented, named issue, not folklore (docs.wisprflow.ai/articles/1621472516).
  - **Cursor / VS Code / IDEs** require explicit Accessibility permission and "Screen Reader Optimized" mode enabled, or dictation reports "Accessibility is not enabled" (docs.wisprflow.ai/articles/6434410694).
  - **iOS external/Apple physical keyboards**: App Store reviews report the app "doesn't function properly if using the Apple Keyboard or external keyboard" and disables the native repeat-dictation feature (apps.apple.com review analysis).
  - **Long-session text loss**, particularly with AirPods, reported repeatedly in App Store reviews (apps.apple.com review analysis).
  - Correction UX friction on iOS: switching to the number/punctuation keyboard to fix a word forces closing and reopening the Flow keyboard — called out as a specific accessibility pain point for users with tremors/mobility issues (apps.apple.com review analysis).

## Accuracy & personalization
- **"Dictionary"** (exact feature name) — personal custom-vocabulary list. Add via Dictionary tab (desktop sidebar / mobile bottom tab) → "Add new"/+ → enter word/phrase → Save. Limits: **60 characters max per entry**; duplicates rejected; **one replacement/correction mapping per word** (not many-to-one); very long phrases rejected. A "Correct a misspelling" toggle lets you map a wrong output to the right spelling explicitly. Entries can be **starred** for higher recognition priority (desktop only). When you manually correct a word during dictation, Flow **auto-adds it to your dictionary**. Syncs across Mac/Windows/iOS/Android. Bulk **CSV import** is desktop-only; Android cannot star/sort/bulk-import or create replacement rules; iOS has no search and no bulk import (docs.wisprflow.ai/articles/4052411709-teach-flow-your-words-with-the-dictionary). Dictionary has three tabs: **All, Personal, Shared with team** (per search summary).
- **"Snippets"** (exact feature name) — voice-triggered text expansion. Say a trigger phrase mid-sentence as a **whole word** (no surrounding punctuation) and Flow expands it — e.g. saying "send the package to my address" outputs "...123 Main Street, San Francisco, CA 94102." **Trigger limit: 60 characters. Expansion limit: 4,000 characters.** Rich-text formatting (bold, links) is preserved in apps that support it; plain-text apps get plain text automatically. **Team snippets** are shared org-wide by admins on Pro/Business/Enterprise plans (docs.wisprflow.ai/articles/5784437944; wisprflow.ai/post/snippets, published **November 12, 2025**).
- **Context Awareness** (exact feature name) — reads the active window's on-screen text/screenshot **at the moment of dictation** to improve proper-noun spelling (e.g., email recipient names) and to pick the right formatting Style. Categorizes the focused app into Email / Work messaging / Personal messaging / Other. **Excludes**: banking/financial apps, Flow's own UI, browser URL/address bars, password fields (auto-excluded on macOS, manual elsewhere), placeholder/hint text, and numeric-only fields. **On by default on Mac/Windows**; toggle at Settings → Data and Privacy; enterprise admins can lock it org-wide to "Disable for all users" (docs.wisprflow.ai/articles/4678293671-feature-context-awareness).
- **Backtrack** (exact feature name) — removes filler words and self-corrections mid-dictation without stopping. Trigger words: **"actually," "scratch that," "never mind,"** or simply restating the correct version (Flow uses surrounding context). Example given in docs: saying "Let's do coffee at 2 actually 3" outputs "Let's do coffee at 3" (docs.wisprflow.ai/articles/5373093536).
- **Dev-specific accuracy features:** file/filename tagging in Cursor/Windsurf carried across dictation sessions as context; camelCase/snake_case/CLI-syntax awareness; recognizes dev jargon by name (Supabase, Cloudflare, Vercel) (wisprflow.ai/features).
- **"Whisper mode"** (exact feature name per marketing) — claimed to function even at low speaking volumes in quiet spaces (wisprflow.ai/features) — contradicted somewhat by App Store reviews claiming the app "only functions reliably in quiet environments" and struggles with real-world ambient noise.

## Formatting & AI cleanup
- **"Styles"** (exact feature name) — 4 tone presets, applied per app-category, not globally:
  | Style | Where available | Effect (Wispr's own wording) |
  |---|---|---|
  | Formal | Personal, Work, Email, Other | "Caps + punctuation" |
  | Casual | Personal, Work, Email, Other | "Caps + less punctuation" |
  | **Very Casual** | Personal messages only | "No caps + less punctuation"; always strips trailing periods |
  | **Excited!** | Work, Email, Other (not Personal) | "More exclamations" |

  Set at Styles (sidebar) → pick category tab (Personal messages / Work messages / Email / Other) → click a style card (docs.wisprflow.ai/articles/2368263928-how-to-setup-flow-styles). App-category auto-detection maps iMessage/WhatsApp/Telegram → Personal; Slack/Teams → Work; Gmail/Outlook/Superhuman → Email; Docs/Notes/ChatGPT → Other. **English/desktop-first** — works best with English dictation; iPhone support was described as "planned" as of the source crawled (Product Hunt changelog "Personalized Styles" entry, per search).
- **Smart Formatting** (exact feature name, always-on by default, cannot be disabled on Android) — automatic punctuation, capitalization, and list formatting; converts spoken sequence words ("one… two…" / "first… second…") into numbered lists; strips trailing periods in detected messaging apps (WhatsApp, Slack, Discord). Toggle at Settings → System → Extras (Mac/Windows) or Settings → Personalization (iOS) (docs.wisprflow.ai/articles/5373093536).
- **Punctuation-by-name** — explicit spoken punctuation commands recognized: **"period"/"full stop"** → `.`; **"em dash"/"em-dash"/"emdash"** → `—`; **"quotation mark"** → `"`; **"new line"/"line break"/"skip a line"** → line break; **"new paragraph"/"start a new paragraph"** → paragraph break (docs.wisprflow.ai/articles/5373093536).
- **Command Mode** (deeper rewrite layer, distinct from Smart Formatting) — after dictating, highlight text, hold the Command Mode shortcut, speak an instruction, release. Documented examples: **"make this more formal," "translate this to Spanish," "turn this into a bullet list."** If nothing is highlighted, Command Mode instead **opens Perplexity in the browser** with the spoken question as a search (e.g., "What's the current price of Tesla stock?"). Requires **Pro plan or higher**; enabled via Settings → Experimental (docs.wisprflow.ai/articles/4816967992-how-to-use-command-mode).
- No explicit "raw vs. polished" toggle was found; the closest equivalent is disabling Smart Formatting entirely (Mac/Windows/iOS only — forced on for Android).
- A separate **"Transforms"** feature (beta, shipped May 1, 2026) is described in the changelog as enabling "AI text rewrites" — likely overlapping with or extending Command Mode; not documented in depth in crawled help articles (wisprflow.ai/whats-new).

## Voice commands
- **Backtrack correction phrases:** "actually," "scratch that," "never mind" (or simply re-stating the intended text) — docs.wisprflow.ai/articles/5373093536.
- **Punctuation commands** (see Formatting section above for full list): "period"/"full stop," "em dash"/"em-dash"/"emdash," "quotation mark," "new line"/"line break"/"skip a line," "new paragraph"/"start a new paragraph."
- **Command Mode instruction phrases** (documented examples only — Flow does not publish a fixed command grammar, it accepts free-form instructions): "make this more formal," "translate this to Spanish," "turn this into a bullet list." Any open-ended question with nothing highlighted routes to a Perplexity web search instead of a text edit.
- **Hands-free submission:** "press enter" mentioned as a spoken command to submit a prompt while in hands-free mode (docs.wisprflow.ai/articles/6391241694, use-case framing).
- Command Mode activation itself has command-like gestures: **double-press** the shortcut = jump straight into hands-free without holding; **triple-press** = dismiss the Command Mode session; `Esc` or `Backspace` = cancel (docs.wisprflow.ai/articles/4816967992).
- **Not confirmed:** generic editing commands like "delete that," "undo," or "select [x]" are claimed by some third-party review sites but could not be confirmed with an exact phrase in any official Wispr Flow doc crawled — flagged as unverified. One official note found: on iOS, voice text-editing commands do not work at all — "use the desktop app instead" (per search summary of navigation doc).
- Command Mode is **gated to paid plans** — inactive entirely on the Free tier.

## Languages & multilingual
- **100+ languages** marketed (104 per Wikipedia's infobox). Tiered: **7 "premier" languages** (French, German, Hindi, Italian, Portuguese, Spanish, Thai) get English-level performance; **75+ more** including Arabic, Cantonese, Dutch, Hebrew, Indonesian, Japanese, Korean, Mandarin, Polish, Russian, Swedish, Turkish, Ukrainian, Vietnamese (wisprflow.ai/research/supporting-languages).
- **Auto-detection is per-session, not per-word or mid-sentence.** Direct quote: "Flow picks a language at the start of each dictation session and transcribes the whole segment in that language." Users can change languages between sessions but **not mid-utterance** (docs.wisprflow.ai/articles/3191899797-use-flow-with-multiple-languages).
- **Code-switching is an explicitly documented weakness**, not a hidden gap: "works best when you speak primarily in one language with occasional words from another." **Chinese–English mixing is named as the single hardest combination** — "English words may appear in Chinese characters or vice versa." For **Hinglish**, users must select a dedicated Hinglish option rather than relying on Hindi or English alone; a March 2026 change improved things so **romanized Hindi** ("tum kya kar rahe ho") now outputs correctly without switching scripts mid-output (docs.wisprflow.ai/articles/3191899797; wisprflow.ai/whats-new).
- **Regional variants supported as distinct options** (not auto-inferred): British English, Canadian English, American English; Swiss German (uses "ss" instead of "ß"); Simplified vs. Traditional Chinese, each with regional pre-fill defaults.
- **Official best-practice advice given to users:** "Select only the languages you actually use — fewer active languages means more accurate detection." For frequent code-switchers, **manually picking 2–3 languages beats relying on Auto-detect** (docs.wisprflow.ai/articles/3191899797). This is effectively an admission that Auto-detect degrades with more active languages.
- **Claimed (unquantified) accuracy improvements:** dynamic per-language ASR engine selection "cuts transcription error rates by more than half in internal testing"; newer non-Whisper ASR options ("Scribe," "Gemini") "drastically outperform OpenAI's Whisper in Asian languages when measured by WER" — no exact WER numbers were published in the crawled post (wisprflow.ai/research/supporting-languages). Roughly 50% of Wispr's users are stated to speak more than one language day-to-day (same source).
- Known language-specific formatting quirks documented: Spanish (letter-dropping, word-mashing, ~20% wordier than English), Italian (intonation-dependent meaning), French (mandatory space before certain punctuation), German (quotation-mark style variation).

## Privacy & data
- **Certifications:** SOC 2 Type II, ISO 27001:2022, HIPAA; also aligns with ISO/IEC 42001:2023, GDPR, and CCPA (docs.wisprflow.ai/articles/6939510703; wisprflow.ai/privacy).
- **Granular controls, all under Settings → Data and Privacy:**
  - **"Improve the model for everyone"** (formerly named "Privacy Mode") — opt-in toggle for whether audio/transcripts/edits may be used to evaluate/train/improve models.
  - **Dictation cloud storage** — toggle for whether transcripts/audio/history persist on Wispr's servers (needed for cross-device history).
  - **Context Awareness** — toggle for whether on-screen text/screenshots are read and sent with a dictation request.
  - **Local data storage** — three choices: Store Normally / Delete After 24h / Never Store.
  - **Notetaker transcript retention** — separately configurable retention window.
  - **Auto-add to Dictionary** — separately toggleable under Settings → Personalization.
  (wisprflow.ai/data-controls)
- **Zero Data Retention (ZDR)** is not a single switch — it is the *combination* of Privacy Mode ON **and** Dictation cloud storage OFF: "no training and no server-side storage of dictation data" (docs.wisprflow.ai/articles/4709791908-understanding-privacy-mode-and-cloud-sync). This means the **privacy-maximal state requires the user to actively find and combine two separate toggles** — it is not the out-of-box default.
- **HIPAA**: healthcare customers can sign a Business Associate Agreement (BAA) directly in-app; Privacy Mode is **automatically locked ON** whenever a HIPAA BAA is active or an enterprise enforces ZDR org-wide.
- Marketing claim: **"We never sell your data. Your data is always in your control."** (wisprflow.ai/privacy). Encrypted in transit and at rest. Public bug bounty **up to $5,000+** for critical vulnerabilities; live compliance status published at **trust.wispr.ai** (wisprflow.ai/privacy).
- Enterprise admins can force org-wide policy (e.g., lock Context Awareness to "Disable for all users") that individual users cannot override (docs.wisprflow.ai/articles/4678293671).
- **Public controversy:** Hacker News post **"Wispr Flow Is Tracking Every App/URL You Visit and Taking Screenshots"** (news.ycombinator.com/item?id=47781148, ~April 2026, sourced from an independent investigation at wensenwu.com) — low engagement (5 points, 1 comment) but the single comment recommended fully local/offline alternatives (SuperWhisper, Handy.computer, Careless Whisper), which is a direct signal that some users actively seek an offline tool for exactly the reason Nasar Flow already satisfies. Multiple third-party review sites independently frame this as an ongoing trust issue: "Does Wispr Flow Take Screenshots? Yes — Here's What That Means" (getspeakup.app) and "Is Wispr Flow Safe? Seven Incidents and Two Toggles You Need to Know" (getvoibe.com) — the "two toggles" framing matches the ZDR-requires-two-settings finding above.
- Because the architecture is 100% cloud-dependent, **no true offline/on-device option exists at all** — this is the single largest structural privacy difference versus Nasar Flow.

## Blog / engineering insights
- **wisprflow.ai/research/supporting-languages** is the most technical first-party post found. Claims: (1) dynamic **per-language ASR engine selection** rather than one model for all languages; (2) fine-tuned formatting models per language for punctuation/spacing/regional conventions; (3) **accent confidence scoring** that compares multiple candidate transcriptions; (4) explicit code-mixing handling for romanized Hindi. Directional (non-numeric) accuracy claims: per-language engine selection "cuts transcription error rates by more than half in internal testing"; newer ASR options ("Scribe," "Gemini") "drastically outperform OpenAI's Whisper in Asian languages when measured by WER" — **no exact WER figures were published**.
- **wisprflow.ai/post/snippets** (Nov 12, 2025) and **wisprflow.ai/post/personalized-style** are feature-announcement posts, light on engineering depth, oriented at end-user use cases (support teams, founders, everyday users).

- **Third-party technical reconstruction** (not confirmed by Wispr directly, treat as informed speculation): pipeline is mic capture → voice-activity detection (start/stop) → ASR (Whisper-family historically) → LLM cleanup pass (filler removal, punctuation) → paste; hosted via **Baseten** on **AWS us-east-1**; Baseten's own infra claims **sub-700ms p99 end-to-end latency**, but real-world user-perceived latency is described as closer to **1–2 seconds** (getvoibe.com/resources/openai-whisper-vs-wispr-flow). ## User complaints (reviews, Reddit, HN, App Store)
- **App Store (iOS)** — 4.8/5 across ~15,000 ratings at time of direct fetch (a separately-summarized third-party source cited "8,500+ ratings," suggesting the count grew between snapshots or sources disagree — flagged) (apps.apple.com/us/app/wispr-flow-ai-voice-keyboard/id6497229487). Recurring negative themes: (1) app requires constant reopening on iPhone/iPad, losing the session mid-use; (2) long-dictation transcript loss, especially over AirPods; (3) unreliable in real-world ambient noise despite "Whisper mode" marketing; (4) correction UX forces closing/reopening the keyboard to reach the number/punctuation layer — flagged as a specific accessibility burden for users with tremors; (5) occasional "processing spiral"/spinner requiring app restart; (6) "not one email request for support answered"; (7) excessive marketing notifications/emails.

Dominant complaint pattern: **the product works well during the 14-day free trial, then reliability visibly degrades after payment begins** — one review specifically states it "works 60% of the time" post-trial. Other clusters: referral-program issues, terms-of-service language concerns, and unresponsive support (one user reported a month of silence; another got no reply after a card-update/billing issue) (search summary of Trustpilot; getvoibe.com "Is Wispr Flow Reliable?").

## Best-practice takeaways
1. One consolidated shortcut-binding settings screen (Settings → General → Shortcuts) that validates each new binding live against OS-reserved combos and existing bindings, rather than scattering hotkey config across multiple menus (docs.wisprflow.ai/articles/2612050838).
2. Offer both push-to-talk and a distinct, explicitly-different hands-free shortcut, plus a fast gesture (double-press) to switch between them without opening settings (docs.wisprflow.ai/articles/6391241694).
3. Give voice-editing/rewriting its own hotkey, entirely separate from the dictation hotkey, so a user never has to exit "record mode" to issue an edit instruction (Command Mode) (docs.wisprflow.ai/articles/4816967992).
4. Make the personal dictionary self-populating: a manual correction during dictation should silently add the corrected spelling to the dictionary with zero extra steps (docs.wisprflow.ai/articles/4052411709).
5. Publish snippet/dictionary character limits (60-char trigger, 4,000-char expansion) up front, and require whole-word trigger matching mid-sentence — this is a deliberate transcription-robustness choice, not an arbitrary product limit (wisprflow.ai/post/snippets).
6. Scope tone/formatting presets to app-category (Personal/Work/Email/Other) rather than a single global tone, since real users write differently across contexts (docs.wisprflow.ai/articles/2368263928).
7. When text insertion can't be verified (long docs, slow apps), fail safe to clipboard + a visible manual "Paste" button rather than silently dropping or duplicating text.
8. Maintain a dedicated, itemized "Known Issues" page (10 live articles) instead of hiding bugs in a general FAQ — it deflects support tickets and visibly signals honesty (docs.wisprflow.ai/collections/5686269587).
9. Ship a public, frequently-dated changelog at a stable URL — near-weekly desktop releases (wisprflow.ai/whats-new) signal active investment to anyone evaluating a switch.
10. Split privacy controls into separately-toggleable primitives (train-on-my-data, cloud storage, context/screen awareness, local retention window) instead of one binary "privacy mode" — but recognize the failure mode: Wispr's own true zero-retention state requires combining two separate toggles, which most users won't discover unprompted (wisprflow.ai/data-controls).
11. Stand up a public compliance/trust page with live cert status and a published bug bounty (trust.wispr.ai) — this is table-stakes for enterprise credibility regardless of company size.

## Ideas Nasar Flow should steal or beat
1. [steal] Build one consolidated shortcut-settings screen with live conflict validation against OS-reserved key combos — directly portable UX, cheap to build, high perceived polish (docs.wisprflow.ai/articles/2612050838).
2. [steal] Add a distinct second hotkey for voice-driven post-dictation instructions ("make this more formal," "translate this to Malay," "turn this into a list") layered on top of raw dictation — and since Nasar Flow is on-device, this instruction-following pass can run fully offline, which Wispr categorically cannot offer (its Command Mode requires a cloud round-trip and a Pro subscription).
3. [beat] Wispr's language handling is per-session, not per-word, and its own docs name Chinese–English as the single hardest code-switching case it does not solve. **This is the exact problem Nasar Flow exists to solve.** Marketing and product docs should explicitly benchmark Nasar Flow's mid-utterance Singlish/Malay/Arabic switching against Wispr's documented "select only the languages you actually use, fewer is more accurate" workaround — Wispr is telling its own users to avoid the very thing Nasar Flow is built for.
4. [beat] Wispr is 100% cloud-dependent with zero offline mode (docs.wisprflow.ai/articles/2772472373) and generated its own "is this spyware" Hacker News thread over Context Awareness screenshot capture. Nasar Flow should lead marketing with an unconditional claim ("we never see your screen, ever — nothing leaves the device") rather than a toggle-dependent privacy story, directly countering the "two toggles you need to know" framing third parties already use against Wispr.
5. [steal] Per-app-category tone presets (Formal/Casual/Very Casual/Excited, scoped to Personal/Work/Email/Other) are cheap and high-value — adapt the categories to local context (e.g., a "WhatsApp family group" preset that keeps Singlish particles like "lah"/"leh"/"one" rather than stripping them as Wispr's Formal/Casual modes would for English).
6. [steal] Publish a small, honest, itemized "Known Issues" page from day one — costs little, builds trust, and reduces duplicate support tickets, matching Wispr's 10-article known-issues collection (docs.wisprflow.ai/collections/5686269587).
7. [beat] Wispr's Trustpilot score (2.7/5) is far below its App Store score (4.8/5), driven by a repeated "works great in the trial, degrades after payment" complaint and unresponsive support — for a company with $335M+ raised. Nasar Flow, as a much smaller/newer product, can win disproportionate trust by keeping review scores consistent across platforms and by actually responding to support requests, which costs little relative to the reputational upside.
8. [beat] Wispr's dictionary/snippet system (60-char whole-word triggers) is designed around space-delimited Latin-script languages. Nasar Flow should treat Jawi/Arabic script and Singlish discourse particles as first-class dictionary/snippet tokens from the start, not bolt them onto an English-first matching engine the way Wispr's docs imply its architecture was originally scoped.
9. [steal] Granular, separately-toggleable privacy settings (train-on-my-data, cloud storage, context awareness, retention window) are good UX for compliance-minded users — but Nasar Flow should market its default state as *already* the privacy-maximal state (nothing to combine, nothing to discover), rather than making users hunt for a "real" zero-retention combination the way Wispr's ZDR requires.
10. [steal] A visible public changelog at a stable URL, updated frequently, is a strong low-cost signal of active development that Nasar Flow should adopt verbatim as a practice (wisprflow.ai/whats-new).
11. [beat] Wispr's documented Command Mode gates all voice-editing behind a paid plan and a cloud round-trip. Since Nasar Flow's ASR/LLM pipeline is already on-device via whisper.cpp, offering even a lightweight version of "voice-edit the last dictation" for free (no subscription, no network) would be a feature Wispr structurally cannot match at the same price/privacy point.
12. [steal] Session-length limits should be generous, clearly signposted, and warn before cutting off (Wispr: 20-minute desktop cap with a warning at 19 minutes) rather than abruptly truncating — good practice regardless of the underlying engine.
