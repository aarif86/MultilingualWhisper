# Talon Voice

> Made by Ryan Hileman (lunixbochs); hands-free computer control (voice + noise + eye-tracking) for power-user developers; free core app + paid Patreon beta tier; not a consumer dictation app but the deepest prior art on command-grammar design for voice-driven text editing.

## Facts
- **Maker / founded / funding:** Built by Ryan Hileman ("lunixbochs"). Funded via Patreon (tiers from $5/mo; $25/mo unlocks the bleeding-edge Beta build) rather than VC (talonvoice.com; patreon.com/lunixbochs). ~50% of the core engine is closed-source; Hileman has privately shared source with trusted community members as a "bus factor" mitigation (handsfreecoding.org/2021/12/12/talon-in-depth-review/).
- **Platforms:** macOS, Windows, Linux (X11). No official iOS/Android — desktop-only (talonvoice.com).
- **Pricing:** Core app + on-device speech engine free forever, royalty-free personal license (talonvoice.com/EULA.txt). Patreon $5/mo = supporter perks; $25/mo = early access to Beta builds + priority Slack support (handsfreecoding.org review; Patreon).
- **Engine:** On-device, no cloud dependency, works fully offline. Primary engine is "Conformer" (their own on-device ASR, branded "W2L Conformer"/"Conformer D"/"Conformer D2"), originally built on a Wav2Letter-derived architecture (IEEE Spectrum reporting; talon.wiki Speech Engines page). Also supports Dragon NaturallySpeaking (Windows-only, via the "Draconity" bridge) as an alternative/complementary engine, and a legacy "W2L Gen2" engine. Dec 2025 changelog announced a new **"Whisper hybrid speech recognition engine"** for improved dictation/mixed-mode recognition, paired with "Conformer D2 + Whisper (2025-01-06)" model combining fast command recognition with Whisper for prose dictation (talonvoice.com/dl/latest/changelog.html). No LLM-based post-processing/cleanup layer — formatting is rule-based (see Formatting section).
- **Languages:** Talon's core Conformer command-recognition model is **English-only** ("Talon's main conformer model only supports English" — talon.wiki Speech Engines). Non-English *dictation* (not commands) is a beta/supplemental feature via bolted-on engines: **Vosk** (on-device, per-language models from Alphacephei) or **WebSpeech** (cloud, requires internet, multi-language) — these only handle prose dictation, command-mode recognition still requires the primary English engine running alongside (talon.wiki). No code-switching / mixed-language-in-one-utterance support of any kind — this is the single biggest structural gap vs. Nasar Flow's Singlish/Malay/Arabic use case.

## Activation & capture UX
Talon is always-listening once launched (no push-to-talk widget model) — it continuously runs the active speech engine and interprets every utterance against whichever **mode** is currently enabled (see Voice commands below for the mode system). There is no mobile-style tap-to-record flow since Talon is desktop-only. Users toggle listening on/off with spoken commands (`go to sleep`, `sleep all`) or a "sleep mode" that mutes recognition; noise-based triggers (a "pop" or hiss detected by the noise engine) can also gate actions like mouse clicks. There is no visual waveform overlay by default in the base app — visual feedback (subtitles/HUD, mic status) is provided by community add-ons like **Talon HUD**, not the core product (handsfreecoding.org).

## Text insertion
Talon issues literal key events / uses OS accessibility & automation hooks to type or paste text into the focused field — the community grammar's `insert()` and `key()` primitives simulate keystrokes (seen throughout text.talon/edit.talon, e.g. `key(modifiers)`, `insert("{text}")`). Because it operates at the OS input level rather than through a keyboard-extension sandbox (as mobile IMEs must), it can freely combine literal text insertion with arbitrary key-chord commands (undo, save, navigate) in the same breath. Per-app **context files** (e.g. `apps/vscode/vscode.talon`) override or extend behavior when a specific app is focused — Talon detects the focused app/window and only activates matching `.talon` files, which is how it avoids clashing with app-native shortcuts.

## Accuracy & personalization
- **Custom vocabulary/homophones:** A CSV-driven homophone system (`core/homophones/homophones.csv`, ~8.7KB of entries) lets users resolve ambiguous words. Spoken commands surface and pick among alternatives: `phones <word>` shows homophones for a word, `phones that` auto-detects from context, `phones word` selects the word under cursor and shows options, `phones [<ordinal>] word left/right` extends selection to a nearby word first, `phones force <word>` forces a lookup, `phones hide|exit` dismisses the popup (core/homophones/homophones.talon).
- **Auto-learning:** No ML personalization/auto-learning from corrections is documented in the crawled sources — accuracy improvements come from engine upgrades (Conformer D → D2), not per-user adaptation.
- **Custom commands/macros:** Since the entire grammar is user-editable Python + `.talon` files, "personalization" in Talon means writing your own commands/snippets rather than the app learning passively — e.g. Josh Comeau's custom `"styled button fancy button"` macro that emits templated React component code with cursor placement (joshwcomeau.com).
- **Per-app context:** Native and central to the design — every context file declares an `app.name`/`os`/title matcher above a `-` divider, and only fires when that app is focused (talonvoice.com/docs/scripting.html; apps/vscode/vscode.talon).
- **Spelling mode:** `spell that <letters>` inserts spelled letters using the NATO-like phonetic alphabet (air/bat/cap/drum for a/b/c/d — joshwcomeau.com), and works inside dictation mode as a correction tool (`spell that <letters>`, `spell that <formatters> <letters>` in dictation_mode.talon).

## Formatting & AI cleanup
No LLM/AI-based cleanup exists — formatting is 100% deterministic, rule-based, and voice-triggered:
- **Case/naming formatters** (spoken *before* dictating a phrase or word): e.g. `camel hello world` → `helloWorld`; `snake hello world` → `hello_world`; composable modifiers like `allcaps snake dark colors` → `DARK_COLORS` (joshwcomeau.com). In the shipped grammar this is the `{user.prose_formatter} <user.prose>` / `{user.word_formatter} <user.word>` pattern (text.talon).
- **Dictation-specific toggles** (only active in dictation mode, dictation_mode.talon): `cap` (capitalize next), `no cap`/`no-caps` (suppress auto-cap), `no space`/`no-space` (suppress auto-space), and retroactive versions `cap that`, `no cap that`, `no space that` that reformat the last-inserted phrase.
- **Correction/undo of dictation:** `nope that` / `scratch that` clears the last dictated phrase; `select that` re-selects the last phrase for further action; `before that` (text.talon) jumps before the last insertion.
- **Formatted paste:** `<formatters> (pace|paste)` reformats clipboard contents before pasting (e.g. "uppercase paste").
- **No raw-vs-polished toggle** in the AI sense — instead there's a binary literal-escape mechanism (see Voice commands) that bypasses all formatting/command interpretation for one phrase.

## Voice commands
This is Talon's defining design and the most transferable IP for Nasar Flow. **Talon has two mutually-exclusive global modes, `command` and `dictation`**, controlled by a tiny mode file (core/modes/command_and_dictation_mode.talon):
```
mode: command
mode: dictation
-
^dictation mode$: user.dictation_mode()
^command mode$: user.command_mode()
```
- In **command mode**, every recognized phrase is matched against the full structured grammar (verbs + modifiers + captures) — nothing is transcribed as free text unless a rule explicitly captures it.
- In **dictation mode** (`mode: dictation`, core/modes/dictation_mode.talon), the grammar swaps almost entirely to a catch-all: `<user.raw_prose>: user.dictation_insert(raw_prose)` — arbitrary speech is transcribed and typed with auto-capitalization/auto-spacing — while a *small whitelist* of dictation-safe commands remains active alongside it: navigation (`go up <n> lines`, `go left <n> words`), selection/deletion (`select left <n> words`, `clear right <n> characters`), formatting toggles (`cap`, `no space`), and corrections (`nope that`/`scratch that`, `spell that <letters>`).
- **The escape hatch** — the single most important mechanism for a consumer dictation app to study — is the literal `escape` command inside dictation mode: `^escape <user.text>$: user.dictation_insert(user.text)`. It lets a user dictate literal text that would otherwise be swallowed as a command word (e.g. saying "escape scratch that" literally inserts "scratch that" as text instead of triggering the clear-last-phrase action).

Representative exact command grammar pulled directly from the shipped repo (talonhub/community, `main` branch):
- **Editing** (core/edit/edit.talon): `select line`, `clear all`, `copy that` → `edit.copy()`, `cut that` → `edit.cut()`, `(pace | paste) (that | it)`, `paste match` (paste-and-match-style), `clone that` / `clone line` (duplicate), `new line above`, `new line below | slap`, `undo that`, `redo that`, `file save`, `file save all`, `indent [more]`, `indent less | out dent`, `zoom in/out/reset`, `find it` (open find), `next one` (find-next), `go way left/right/up/down` (line/file start/end), `go top`/`go bottom`, `[go] line mid`.
- **Navigation chains** (core/edit/edit.talon): `go <user.navigation_step>+` — supports chained multi-step phrases like "go left left down" or "go 5 left 2 down" and "go word left"/"go 2 words right", resolved by `user.perform_navigation_steps()`.
- **Phrase/dictation utilities** (core/text/text.talon): `phrase <text>` inserts spoken text and logs it to history; `recent list` toggles a phrase-history panel; `recent repeat <n>` re-inserts the nth recent phrase; `recent copy <n>` copies it to clipboard; `select that` selects the last phrase; `nope that | scratch that` clears it; `nope that was <formatters>` reformats the last phrase with new case rules; `(abbreviate | abreviate | brief) {abbreviation}` expands text-expansion snippets.
- **Homophone disambiguation** (core/homophones/homophones.talon): `phones <word>`, `phones that`, `phones word`, `phones force <word>`, `phones hide | exit`.
- **Sleep/wake** (core/modes/sleep_mode.talon): `go to sleep [<phrase>]` disables recognition; `sleep all [<phrase>]` disables recognition AND hides all Talon UI (switcher, history, homophones, help, mouse grid) in one shot — deliberately designed so a user can say "sleep all hey bob" and immediately talk to a human without a timeout delay (comment in source explains this explicitly).
- **App-specific example** (apps/vscode/vscode.talon): verb+noun command patterns like "bar explore" (focus sidebar/explorer), "symbol hunt"/"file hunt" (fuzzy search), git operations (commit/push/pull/branch), breakpoint/debug stepping commands, and AST-aware "smart selection" expand/shrink commands.

## Languages & multilingual
English-only for command recognition (talon.wiki). No auto language-detection and **no code-switching support** — the entire grammar-matching design assumes a single fixed language's phonetic/lexical space (letters are single-syllable English words like "air/bat/cap/drum"; formatters like "camel"/"snake" are English keywords). Non-English dictation exists only as a bolted-on beta path (Vosk on-device per-language models, or WebSpeech cloud) that still requires the English command engine running in parallel to catch mode-switch phrases (talon.wiki Speech Engines page). No translation feature. This is a hard architectural wall for anything like Singlish/Malay/Arabic code-switching — Talon was simply never designed for it.

## Privacy & data
- **On-device by default:** Primary Conformer engine runs fully locally; "disconnect from the internet and it still works," no cloud round-trip for audio, no telemetry on speech/text/screen content (per third-party privacy roundups referencing talonvoice.com/EULA.txt).
- **What is collected (per EULA.txt):** IP address + app version logged periodically by the update server if auto-update is enabled; anonymized performance metrics and feature-usage ratios keyed to a random token (explicitly excludes "actual input, speech, text, or screen contents"); crash reports auto-uploaded on next launch after a crash. Connections use TLS; servers described as full-disk-encrypted with restricted access.
- **No SOC2/HIPAA claims** found in any crawled source — Talon is a hobbyist/prosumer tool, not enterprise-certified.
- **Licensing quirks:** Non-transferable personal license; eye-tracking data may not be stored for research/commercial use; reverse-engineering limited to personal knowledge; community-contributed grammar is auto-licensed BSD Zero Clause unless stated otherwise (talonvoice.com/EULA.txt).

## Onboarding & docs
Docs are organized as: Introduction → Getting Started → Getting Scripts → Learning Talon → `.talon` Files reference → API Reference (talon, talon.app, talon.clip, talon.fs, talon.noise) (talonvoice.com/docs/). Official docs skew toward isolated Python API examples rather than a cohesive conceptual walkthrough — reviewers explicitly call this out as the product's weakest point, saying the unofficial community wiki (talon.wiki) and Slack are "essential supplements" (handsfreecoding.org). There is no first-run interactive tutorial in the core app; new users are expected to install the separate community grammar repo (`talonhub/community`, via git clone into `~/.talon/user`) to get a usable command set at all — the base Talon install ships with almost no commands of its own. An external interactive trainer exists (chaosparrot.github.io/talon_practice/) built by the community, not the vendor. Speech-engine setup (installing Conformer) is done through Talon's own "Speech Recognition" menu post-install.

## Blog / engineering insights
- IEEE Spectrum's "Programming by voice may be the next frontier" situates Talon's original speech engine as derived from Facebook's **Wav2Letter** ASR architecture, before Talon built its own "Conformer" branded engine on top (search-indexed summary; original spectrum.ieee.org article link returned 404 on direct fetch, so architecture claim is corroborated via search snippet only — flag as secondary-sourced).
- handsfreecoding.org's in-depth review is the most technically detailed third-party writeup found: it frames Talon's `.talon` + `.py` dual-file structure (declarative grammar file + imperative Python action implementations) as a deliberate separation of concerns, and highlights that update-in-place context overriding ("per-context action overrides") is intentionally designed to prevent community grammar fragmentation/forking while still allowing deep customization.
- Josh Comeau's writeup frames Talon commands as "functions with arguments" (e.g., saying "focus chrome" ≈ calling `focus("chrome")`), a mental model explicitly aimed at programmers, and notes working at roughly 50% of normal typing speed but with unchanged "thinking speed," plus the real cost of vocal fatigue across 8-hour days.

## User complaints (reviews, Reddit, HN, App Store)
- **Steep learning curve, by far the most repeated complaint** — "the first two weeks are slow and frustrating"; power users report spending weeks building a personal command set on top of the community grammar before the tool "feels good" (search-aggregated Reddit/review commentary; corroborated by handsfreecoding.org noting the community grammar itself takes real time investment even for experienced Dragonfly users).
- **Conformer accuracy still trails Dragon** in ambiguous/edge-case audio, though the gap is closing with each model release (handsfreecoding.org; talon.wiki).
- **Dictation-mode prose formatting lags Dragon**, particularly automatic number formatting (handsfreecoding.org).
- **Documentation gaps** — official docs are API-reference-shaped, not tutorial-shaped; users lean on the unofficial wiki and Slack (handsfreecoding.org; talonvoice.com/docs/ structure itself confirms the API-first shape).
- **Closed-source dependency risk** — ~50% of the engine is proprietary and tied to one maintainer; mitigations (shared source escrow, promised community-continuation plan) are informal, not contractual (handsfreecoding.org).
- **No native mobile support and no packaged installer simplicity for non-developers** — the entire ecosystem (git-clone-based grammar installation, Python scripting, per-app `.talon` files) assumes a developer-comfortable user; this is a real adoption wall for non-technical users (inferred from install flow in README.md and docs structure).
- **Vocal fatigue** using voice all day is a recurring theme across HN threads and blog writeups (news.ycombinator.com/item?id=30340079; joshwcomeau.com).

## Best-practice takeaways
1. **Two-mode architecture (command vs. dictation) as first-class, explicitly named states**, switchable by voice itself (`command mode` / `dictation mode`) — not an implicit heuristic.
2. **A literal-text escape hatch inside command-shaped grammar** (`escape <text>` inserts text verbatim even if it matches a command phrase) — solves the "how do I dictate the words 'scratch that'" problem cleanly.
3. **A small, curated whitelist of commands that remain active *inside* dictation mode** (navigation, selection, delete, cap/no-cap/no-space, scratch-that, spell-that) rather than either (a) disabling all commands during dictation or (b) letting the full command grammar collide with free speech.
4. **Retroactive correction targeting "the last phrase," not just "the last character"** — `nope that`/`scratch that`, `select that`, `cap that`, `no space that` all operate on a tracked "last inserted phrase" unit, which is more forgiving than undo-by-keystroke.
5. **Composable, spoken case/naming formatters** ("camel", "snake", "allcaps") that stack (`allcaps snake dark colors` → `DARK_COLORS`) — a deterministic, zero-latency alternative to LLM-based formatting for structured text.
6. **Homophone-specific disambiguation as its own UI mode** (`phones <word>`) rather than silently guessing — surfaces the ambiguity to the user with numbered choices.
7. **Per-app context files that activate only when that app has focus**, letting the same spoken phrase mean different things (or nothing) depending on the foreground app, with zero runtime cost when not matched.
8. **Chainable multi-step navigation grammar** (`go left left down`, `go 5 left 2 down`) — lets power users compose primitive movements into one utterance instead of multiple round-trips.
9. **A single "get out of everything, fast" command that also mutes UI** (`sleep all`) explicitly designed to avoid an awkward transcription delay when a human interrupts you — a real-world UX insight about voice tools living alongside human conversation.
10. **Transparent, narrowly-scoped telemetry disclosure** (EULA explicitly states audio/text/screen content is never collected, only anonymized usage ratios/IP/crash reports) — a simple trust-building disclosure pattern.

## Ideas Nasar Flow should steal or beat
1. **[steal] Explicit command-mode/dictation-mode toggle with a literal-text escape hatch.** Nasar Flow's Singlish/Malay/Arabic dictation will constantly produce words that collide with any future voice-command vocabulary (e.g. if "delete" or "baru" ever becomes a command trigger). Ship a Talon-style `escape <phrase>` or double-tap-to-insert-literally mechanism now, before adding any voice commands, so this is never a retrofit problem.
2. **[beat] Multilingual-native command grammar, not an English-only core with bolted-on foreign dictation.** Talon's command layer is hard-English and treats other languages as a second-class dictation-only add-on requiring a second parallel engine. Nasar Flow's whisper.cpp-based, code-switch-aware core should let any future command words be spoken in Singlish/Malay/Arabic too — this is a direct structural advantage Nasar Flow can claim Talon cannot retrofit.
3. **[steal] "Last phrase" as the unit of correction**, not "last character": implement `scratch that` / `nope that`-equivalent commands that undo the entire last dictated utterance, and a `select that` to re-target it for reformatting — much lower cognitive cost than character-level undo on mobile.
4. **[steal] Deterministic, instant case/format commands as a fast-path alongside (not instead of) AI cleanup.** Even with an LLM formatting layer, offering a zero-latency spoken "capitalize that" / "no space" toggle (Talon's `cap`/`no cap`/`no space`) covers the common case without waiting on a model call.
5. **[beat] Ship the escape hatch and correction commands as native mobile keyboard-extension gestures/phrases from day one**, something Talon fundamentally cannot do (desktop-only, git-clone-based grammar install). Nasar Flow's mobile-first, zero-setup positioning is already a structural win against Talon's developer-only installation flow — lean into "works out of the box, no `.talon` file editing" as explicit marketing language.
6. **[steal] Narrow, explicit privacy disclosure language** ("we never collect your audio, text, or screen content — only anonymized crash/usage stats") modeled on Talon's EULA transparency, which reviewers cite as a trust signal.
7. **[beat] Talon's Whisper-hybrid pivot (Dec 2025) validates whisper.cpp as the right bet for dictation quality — but Talon only bolted it onto a 2018-era command-grammar core.** Nasar Flow can market itself as "Whisper-native from day one" vs. Talon's "Whisper retrofitted onto a legacy phonetic-alphabet command system," with the accuracy/latency benefits of a from-scratch design.
8. **[steal] Homophone disambiguation as a discoverable, explicit micro-UI** rather than silent best-guess — worth prototyping for Singlish/Malay homophone pairs where whisper.cpp is likely to guess wrong (tone/dialect-dependent minimal pairs).
