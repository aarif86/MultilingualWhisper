# Serenade

> Made by Serenade Labs (now community-maintained fork); open-source voice-coding tool that lets developers write/edit/navigate code via natural-language commands instead of literal dictation or a fixed grammar; for programmers, especially those with RSI or other conditions that make typing painful.

## Facts
- **Maker / founded / funding:** Serenade Labs, founded ~2019 by Tommy MacWilliam and Matt Wiethoff. Wiethoff developed a repetitive strain injury (RSI) in 2019 severe enough that "typing at a keyboard for even a few minutes caused immense hand pain," forcing him to leave his job as a Quora engineer — the direct origin of the product ([Creating Serenade](https://serenade.ai/blog/creating-serenade/), [IEEE Spectrum](https://spectrum.ieee.org/programming-by-voice-may-be-the-next-frontier-in-software-development)). Raised **$2.1M seed** in Nov 2020 led by Amplify Partners and Neo, alongside launch of a commercial "Serenade Pro" tier ([Voicebot.ai](https://voicebot.ai/2020/11/24/speech-to-code-startup-serenade-raises-2-1m-and-launches-commercial-platform/)). Fully **open-sourced under Apache 2.0** on June 8, 2022 ([Open-Sourcing Serenade](https://serenade.ai/blog/open-sourcing-serenade/)). The company's own development then stalled for roughly **3 years with no repo activity**; a community group forked it (github.com/sombrafam/serenade) and shipped a "first community release" around Jan 2025 ([HN](https://news.ycombinator.com/item?id=42724370), [Lobsters](https://lobste.rs/s/m2daem/serenade_tool_for_coding_with_voice_first)). This pricing/business-model arc — free → paid Pro tier → open-sourced → company goes quiet → community fork — is itself a cautionary data point for any voice-input startup with a small niche market.
- **Platforms:** macOS, Windows (local/on-device recognition requires WSL + Ubuntu), Linux. Editor/app plugins: VS Code, Atom, JetBrains IDEs, Chrome, Hyper terminal, iTerm2 ([GitHub](https://github.com/serenadeai/serenade), [docs](https://serenade.ai/docs/)). No iOS/Android app — it is a desktop dev-tool, not a mobile dictation product.
- **Pricing:** At commercial launch (2020): free cloud-based tier + paid **Serenade Pro** (fully on-device speech engine + on-device code transformation, faster and privacy-preserving) ([Voicebot.ai](https://voicebot.ai/2020/11/24/speech-to-code-startup-serenade-raises-2-1m-and-launches-commercial-platform/)). After the 2022 open-sourcing no further pricing tiers are documented; the current community fork is free/open-source with no evidence of a paid tier.
- **Engine:** Purpose-built speech-to-text engine trained specifically for programming (not a repurposed conversational ASR like Google's) plus a separate NLP/ML layer that maps spoken *intent* ("list of string") to syntactically valid code ("List\<String\>") per target language ([Better Programming](https://betterprogramming.pub/code-by-voice-using-serenade-5f51f4153854), [IEEE Spectrum](https://spectrum.ieee.org/programming-by-voice-may-be-the-next-frontier-in-software-development)). Speech engine itself is 3 models: acoustic model, language model, noise-detection model ([A New Speech Engine](https://serenade.ai/blog/a-new-speech-engine-june-2020/)). Selectable cloud vs. local/on-device recognition server ([docs](https://serenade.ai/docs/)).
- **Languages:** Programming-language support, not human-language multilingual — JS/TS, Python, Java, Kotlin, Dart, etc., added incrementally via dated releases (e.g., JetBrains/Kotlin/Dart Oct 2020; "Next Generation of Language Support" Feb 2022), with auto-detection of the active language from the editor/file context ([docs](https://serenade.ai/docs/), [blog index](https://serenade.ai/blog/)). No evidence of non-English spoken input or code-switching support — a clean whitespace next to Nasar Flow's Singlish/Malay/Arabic angle, just in a totally different domain (spoken code vs. spoken prose).

## Activation & capture UX
Toggle-based, not push-to-talk: default hotkey **Alt+Space** switches listening on/off ([docs](https://serenade.ai/docs/)). A **"mini-mode"** compact overlay was added (Jan 2021 blog) for a smaller on-screen footprint while listening. Live transcript feedback streams to an overlay as you speak; pre-2020-upgrade this refreshed only every ~700ms, later engine work made refresh markedly more frequent as part of a broader ~50% faster decode / ~60% faster end-to-end latency improvement ([A New Speech Engine](https://serenade.ai/blog/a-new-speech-engine-june-2020/)). No mobile capture flow, no watch/widget — desktop-only, editor-focused capture.

## Text insertion
Primary path is **native editor/app plugins** (VS Code, Atom, JetBrains, Chrome, Hyper, iTerm2) that insert code directly via each app's own extension API, giving Serenade precise cursor/selection control inside supported editors ([GitHub](https://github.com/serenadeai/serenade)). For apps without a dedicated plugin or with poor accessibility support, Serenade falls back to a **"Revision Box"** — a proxy text box you dictate into, which is then transferred into the target app ([docs](https://serenade.ai/docs/)). A public **Serenade Protocol** lets third parties build custom plugins/integrations for arbitrary apps beyond the officially supported list ([Creating Custom Plugins with the Serenade Protocol](https://serenade.ai/blog/), [serenadeai/protocol](https://github.com/serenadeai/protocol)) — i.e., they solved "unsupported app" not by an accessibility-API free-for-all but by exposing a stable client protocol for the community to extend.

## Accuracy & personalization
The standout mechanic: the speech/language model reads the **currently open file as context**, so it upweights identifiers already in scope (variable, function, class names) rather than treating them as out-of-vocabulary noise — the docs' own example is learning that an unusual word like "docusaurus" is much more likely given the file content and ranking it top of the alternatives list ([A New Speech Engine](https://serenade.ai/blog/a-new-speech-engine-june-2020/)). When still ambiguous, Serenade shows a **confidence-ranked list of alternative interpretations** for the user to pick from, rather than forcing a repeat-and-hope loop ([Creating Serenade](https://serenade.ai/blog/creating-serenade/)). Users can **opt in** (off by default) to share voice data to help improve the shared ML models ([docs](https://serenade.ai/docs/)). Internally Serenade tracks accuracy via **recall@1 / recall@5 / recall@10** (how often the correct transcript is the 1st / in the top-5 / in the top-10 candidates) — their 2020 speech-engine rewrite reported 35% / 57% / 60% error-rate reductions respectively on these metrics ([A New Speech Engine](https://serenade.ai/blog/a-new-speech-engine-june-2020/)).

## Formatting & AI cleanup
There's no prose "cleanup" layer (no filler removal, tone modes) because the output isn't prose — Serenade's NLP layer's entire job *is* formatting: it converts a spoken description of intent into syntactically correct code for the active language. E.g. saying "list of string" emits `List<String>`; saying "add function factorial" emits a properly-scaffolded function stub with correct braces/indentation/language-specific syntax, and it auto-detects which language's rules to apply from the editor/file extension ([Better Programming](https://betterprogramming.pub/code-by-voice-using-serenade-5f51f4153854), [docs](https://serenade.ai/docs/)). This is the single most relevant transferable idea: **"formatting" is domain-specific, and the app should own the entire mapping from spoken intent to the target's correct native syntax**, not just clean up disfluencies.

## Voice commands
Commands are **natural-language phrases**, not a fixed/spelled grammar. Documented core vocabulary: `add [code]`, `insert [code]`, `change [old] to [new]`, `delete [selector]`, `go to [selector]`, `next/previous [element]`, `line [number]`, `copy/cut/paste [selector]`, `indent/dedent [selector]`, `comment/uncomment [selector]`, `duplicate [selector]`, `save`, `undo/redo`, `focus [app]`, `press [key combination]` ([docs](https://serenade.ai/docs/)). Real HN-cited examples: "delete second function," "add class person," "delete import," "add function factorial" ([HN launch thread via search index](https://news.ycombinator.com/item?id=25191635)). This is explicitly the anti-Talon design choice — see next section.

## Languages & multilingual
Multilingual here means **programming languages**, not spoken human languages: JavaScript/TypeScript, Python, Java, Kotlin, Dart and others were rolled out over time (JetBrains/Kotlin/Dart in Oct 2020; a broader "Next Generation of Language Support" overhaul in Feb 2022), with the active language auto-detected from the editor's current file/mode rather than requiring the user to declare it ([docs](https://serenade.ai/docs/), [blog index](https://serenade.ai/blog/)). No evidence anywhere in docs, blog, GitHub, or third-party coverage of non-English spoken input, accents, or code-switched speech recognition — Serenade's "multilingual" axis is entirely orthogonal to Nasar Flow's.

## Privacy & data
Users choose **cloud-based** or **local/on-device** speech recognition (local requires WSL+Ubuntu on Windows) ([docs](https://serenade.ai/docs/)). At commercial launch, the paid **Serenade Pro** tier ran the speech engine *and* code transformation entirely on-device, marketed explicitly as solving "privacy and security concerns for developers" who can't send proprietary source code to a cloud API ([Voicebot.ai](https://voicebot.ai/2020/11/24/speech-to-code-startup-serenade-raises-2-1m-and-launches-commercial-platform/)). Data sharing to improve shared ML models is **opt-in**, not default ([docs](https://serenade.ai/docs/)). Enterprise proxy-server support existed by Jan 2021 (per blog index). No SOC2/HIPAA claims found anywhere in the crawled material — privacy positioning rests entirely on the on-device option, not on compliance certification.

## Onboarding & docs
Docs (serenade.ai/docs/) walk through: download/install → install the plugin for your target app (VS Code/Chrome/Hyper/etc.) → complete **interactive in-app tutorials** that have you practice real voice commands → configure cloud vs. local recognition server → toggle listening with Alt+Space ([docs](https://serenade.ai/docs/)). Docs are organized around a command reference (grouped by action: create, navigate, edit, system control) plus separate protocol docs for developers building custom integrations. Tone is technical/developer-terse, not consumer-friendly — appropriate for its audience but a contrast point for a consumer dictation app's onboarding, which needs far more hand-holding.

## Changelog & velocity
Company-era cadence was roughly one feature blog post every 1–3 months, 2020–2022: Creating Serenade (May 2020) → New Speech Engine (Jun 2020) → Chrome support (Jun 2020) → JetBrains/Kotlin/Dart (Oct 2020) → $2.1M raise + commercial launch (Nov 2020) → Mini-Mode (Jan 2021) → Custom Plugins/Protocol (Mar 2021) → Terminal/iTerm2 support (Apr 2021) → Ecosystem expansion (Jun 2021) → Next-gen language support (Feb 2022) → Open-sourced under Apache 2.0 (Jun 2022) ([blog index](https://serenade.ai/blog/)). Then a roughly **2.5-year void** with no company shipping activity, ending only with a **community fork's first release around Jan 2025** ([HN](https://news.ycombinator.com/item?id=42724370), [Lobsters](https://lobste.rs/s/m2daem/serenade_tool_for_coding_with_voice_first)) — i.e., in the last 6 months (Mar–Sep 2026) the only "velocity" is whatever the volunteer fork community is doing on GitHub/Discord, not a company changelog.

## Blog / engineering insights
- **"A New Speech Engine" (Jun 2020)** — the deepest engineering post: 3-model pipeline (acoustic, language, noise-detection), all "state-of-the-art" and trained on larger datasets than the prior version; context-injection from the open file so uncommon in-scope identifiers get upweighted; recall@1/5/10 as the accuracy metric family (35%/57%/60% error-rate reduction); ~50% faster decoding and ~60% faster end-to-end latency ([serenade.ai/blog/a-new-speech-engine-june-2020](https://serenade.ai/blog/a-new-speech-engine-june-2020/)).
- **"Open-Sourcing Serenade" (Jun 2022)** — splits the system into a local **client** vs. remote **online services** (speech engine, code engine, core application) plus offline model-training pipelines, all now Apache 2.0; contributions require a core-team sign-off via GitHub Issues first specifically to keep the UX coherent across community changes ([serenade.ai/blog/open-sourcing-serenade](https://serenade.ai/blog/open-sourcing-serenade/)).
- **Founder philosophy** (IEEE Spectrum, quoting cofounder Tommy MacWilliam): "Being able to describe what you want to do is so much easier... more fluid to say 'move these three lines down'" than to spell out a literal command grammar; the broader bet is that "if they can think about the code... then we can have machine learning take the last mile and translate those thoughts into syntactically valid code" ([IEEE Spectrum](https://spectrum.ieee.org/programming-by-voice-may-be-the-next-frontier-in-software-development)).

## User complaints (reviews, Reddit, HN, App Store)
- **Learning curve / enunciation:** review aggregators note voice recognition "takes getting used to" and requires clear enunciation to work reliably (TrustRadius, via search snippets — direct page blocked by Cloudflare).
- **Company abandonment confusion:** the 2025 fork threads show real user confusion about what happened to the commercial product — one Lobsters commenter asks bluntly "Wasn't it commercial?" after being told the original repo saw no activity for ~3 years ([Lobsters](https://lobste.rs/s/m2daem/serenade_tool_for_coding_with_voice_first)); this reads as latent frustration that a promising, funded tool went dark with no communication.
- **Natural-language vs. control tradeoff (implicit, from Talon comparisons):** Talon users on HN point to Talon's precision (literal, spelled grammar plus eye-tracking/mouth-click for cursor control) as the tradeoff Serenade makes for approachability — Serenade is easier to start with but the price is occasional ambiguous-command misfires that fall through to its alternatives-list disambiguation UI ([HN thread indexed via search](https://news.ycombinator.com/item?id=30340636), [IEEE Spectrum](https://spectrum.ieee.org/programming-by-voice-may-be-the-next-frontier-in-software-development)).
- **Platform gap:** no iOS/Android product at all — irrelevant to mobile users by design, not by oversight, but a real complaint-shaped gap if anyone approaches it looking for mobile.

## Best-practice takeaways
1. **Context-aware vocabulary boosting**: feed the current document/screen context into the recognition model so in-scope proper nouns/identifiers/rare words are upweighted rather than treated as noise — Serenade's "docusaurus ranks top of alternatives because it's in the open file" trick generalizes directly to boosting names in a user's contacts, recent messages, or on-screen text.
2. **Confidence-ranked alternatives UI**: when the top transcript is uncertain, surface a short ranked list for one-tap correction instead of silently guessing or forcing a full repeat.
3. **Recall@1/5/10 as the internal accuracy metric**: a clean, comparable way to measure "did the user get the right result without intervening" vs. "was it recoverable within N tries" — worth adopting as an internal eval standard.
4. **Toggle activation with a compact "mini-mode" overlay**: minimizes screen real estate while still showing live transcript feedback.
5. **Publish a stable client protocol** (Serenade Protocol) so third parties/community can extend app support instead of the core team having to hand-build every integration.
6. **Opt-in-by-default data sharing**, not opt-out — a trust-building default worth mirroring.
7. **On-device tier explicitly marketed on the privacy angle** ("your code never leaves your machine") — a clear, simple story for a paid tier's value proposition.

## Ideas Nasar Flow should steal or beat
1. **[steal]** Context-aware vocabulary weighting: bias Nasar Flow's decoder toward names/terms already present on-screen or in the active app's visible text (contact names, recent message contents), the same way Serenade biases toward identifiers in the open file.
2. **[steal]** Confidence-ranked alternatives list for ambiguous output, surfaced inline for one-tap fix, instead of forcing users to just redo the whole utterance.
3. **[beat]** Serenade's command vocabulary is natural-language but still a closed, memorized set ("add", "delete", "go to", "focus", "press") — Nasar Flow should go further and let *editing* commands ("delete that," "change X to Y," "add a comma there") work in Singlish/Malay/Arabic-inflected phrasing too, not just in canonical English, since that's the actual gap Talon-style and Serenade-style tools leave for code-switching speakers.
4. **[beat]** Serenade's business model history (free → paid Pro → open-sourced → company goes dark for 2.5 years → community fork) is a warning, not a template: Nasar Flow's offline-first, no-subscription-dependency architecture (already the design) should be marketed explicitly as "this keeps working even if we go quiet" — a durability promise Serenade's own users learned the hard way to want.
5. **[steal]** Publish a stable "protocol"/API for third-party app integrations early, the way Serenade did, rather than only hand-building support for a fixed app list — lets community/partners extend keyboard-extension reach into apps Nasar Flow hasn't prioritized.
6. **[beat]** Serenade tracks recall@1/5/10 internally but never publishes ongoing numbers publicly — Nasar Flow could differentiate by publishing transparent, dated accuracy benchmarks (e.g., per-language WER, code-switch accuracy) the way few dictation competitors do, turning an internal eval metric into a public trust signal.
7. **[beat]** Serenade's on-device tier was paywalled (Pro-only) even though it's the more private, more trustworthy option — Nasar Flow's whisper.cpp offline-by-default posture beats this by making the privacy-preserving mode the *default and free* experience, not a premium upsell.
